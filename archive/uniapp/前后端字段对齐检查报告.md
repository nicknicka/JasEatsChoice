### 2. 商家 API 参数类型问题 ✅

**问题描述**：
- 错误信息：`参数类型错误：latitude 应是 Double 类型`
- 原因：前端传递的 latitude/longitude 可能是字符串类型

**修复方案**：
- ✅ 在 `merchant.js` 的 `getNearby` 方法中添加类型转换
- ✅ 使用 `Number()` 确保参数为数值类型
- ✅ 添加 null/undefined 检查

**修复代码**：
```javascript
getNearby: (params) => {
  const processedParams = {}
  if (params) {
    if (params.latitude !== undefined && params.latitude !== null) {
      processedParams.latitude = Number(params.latitude)  // 确保是 Double 类型
    }
    if (params.longitude !== undefined && params.longitude !== null) {
      processedParams.longitude = Number(params.longitude)
    }
    if (params.radius !== undefined && params.radius !== null) {
      processedParams.radius = Number(params.radius)
    }
    if (params.limit !== undefined && params.limit !== null) {
      processedParams.limit = Number(params.limit)
    }
  }
  return get(MERCHANT_API.GET_NEARBY_MERCHANTS, processedParams)
}
```

**后端接口定义**：
```java
@GetMapping("/nearby")
public ResponseResult<?> getNearbyMerchants(
    @RequestParam(required = false) Double latitude,   // 要求 Double 类型
    @RequestParam(required = false) Double longitude,  // 要求 Double 类型
    @RequestParam(defaultValue = "5000") Double radius,
    @RequestParam(defaultValue = "10") Integer limit
)
```

## 二、API 枚举化重构

- 包含所有 API 端点的枚举定义
- 提供 `buildUrl` 辅助函数处理路径参数

✅ **banner.js** - 轮播图 API

✅ **user.js** - 用户 API
✅ **dish.js** - 菜品 API
✅ **order.js** - 订单 API

### 枚举使用示例

**旧方式**（硬编码 URL）：
```javascript
getDetail: (bannerId) => get(`/v1/banners/${bannerId}`)
```

**新方式**（使用枚举）：
```javascript
import { BANNER_API, buildUrl } from '../urlEnum'

getDetail: (bannerId) => get(buildUrl(BANNER_API.GET_DETAIL, { bannerId }))
```

**优势**：
- ✅ 统一管理所有接口地址
- ✅ 后端路径变更时只需修改枚举文件
- ✅ 避免路径拼写错误
- ✅ 便于快速查看系统所有接口
- ✅ 支持路径参数自动替换

## 三、需要注意的字段对齐问题

### 1. 数值类型字段

以下字段需要确保传递正确的数值类型：

| 字段名 | 类型 | 说明 |
|-------|------|------|
| latitude | Double/Number | 纬度，必须转换为数值类型 |
| longitude | Double/Number | 经度，必须转换为数值类型 |
| radius | Double/Number | 半径，必须转换为数值类型 |
| price | BigDecimal/Number | 价格，确保传递数值而非字符串 |
| calories | Integer/Number | 卡路里，确保传递数值 |
| rating | BigDecimal/Number | 评分，确保传递数值 |

**前端处理建议**：
```javascript
// 确保数值类型
const params = {
  latitude: Number(locationStore.latitude),
  longitude: Number(locationStore.longitude),
  price: Number(dishPrice)
}
```

### 2. ID 字段命名差异

部分接口存在多种 ID 命名方式，后端通常同时返回：

| 资源 | 主ID | 别名ID | 说明 |
|-----|------|-------|------|
| Banner | bannerId | id | 优先使用 bannerId |
| Merchant | merchantId | id | 优先使用 merchantId |
| Dish | dishId | id | 优先使用 dishId |
| Order | orderId | id | 优先使用 orderId |
| User | userId | id | 优先使用 userId |

**前端处理建议**：
```javascript
// 兼容多种命名
const id = banner.bannerId || banner.id
const merchantId = merchant.merchantId || merchant.id
```

### 3. 图片字段命名差异

| 资源 | 图片字段 | 别名字段 |
|-----|---------|---------|
| Banner | imageUrl | image |
| Merchant | avatar | logo, coverImage |
| Dish | image | imageUrl, coverImage |

**前端处理建议**：
```javascript
// 兼容多种命名
const image = banner.imageUrl || banner.image
```

### 4. 评分字段命名差异

| Merchant | rating | score |

### 4. 响应格式

```json
{
  "success": true,
  "code": "200",
  "message": "成功",
  "data": {}
}
```

**前端处理**：
```javascript
if (res.success === true || res.code === '200' || res.code === 200) {
  // 成功处理

} else {
  // 失败处理

}
```

```javascript
 * 安全获取资源图片
```
