# 小程序端后续分包收口清单

## 目标

- 在首轮主流程可用的基础上，统一页面路径引用方式
- 清理残留的旧路径、源码路径、未分包路径写法
- 不额外改业务结构，只做路径一致性收口

## 第一批：仍会影响用户端体验的入口

1. 清理消息相关页面里残留的旧路径
2. 清理收藏、历史、搜索等外围页面未覆盖到的旧跳转
3. 清理支付、聊天、通知、团购等跨页模块里残留的旧路径

## 第二批：统一路由调用方式

1. 优先改成使用 `src/constants/routes.js`
2. 对带参数的常见跳转优先改成使用 `src/utils/router.js`
3. 逐步减少页面内手写字符串路径

## 第三批：全量对账

1. 对照 `src/pages.json` 导出所有真实注册页面
2. 全局搜索以下高风险写法并逐条消除
   - `/src/pages-user/...`
   - `/pages/order/...`
   - `/pages/merchant/...`
   - `/pages/dish/...`
   - `/pages/index/index`
   - `/cart/index`
3. 对保留页面做三类标记
   - 已注册且可用
   - 已注册但未联通
   - 未注册，仅占位

## 第四批：处理“常量存在但页面不存在”的入口

1. 核对“我的”页保留菜单
2. 删除无页面支撑的无效常量，或者补真实页面
3. 避免出现“代码看起来统一了，但常量本身就是错的”情况

## 验收标准

1. `pages.json` 中每个用户主流程页面，都能从至少一个真实入口到达
2. 用户端关键页面不再直接书写源码路径
3. 全局搜索不再出现首轮主流程中的高风险旧路径模式
4. 微信开发者工具里主流程回归通过
