# 0007 — AI 运行时配置首期单实例

## 背景

AI 运行时配置使用进程内不可变快照和动态模型代理，运行时 key 写入当前后端实例挂载的受限文件。非密钥配置和回滚历史持久化到数据库，但进程内模型客户端缓存、正在执行的请求引用和 key 文件不是跨实例共享资源。

## 决策

首期只支持单后端实例。管理端 AI 模型页面明确提示运行时配置和 key 只在当前实例生效，不会广播到其他实例。多实例部署不在本切片范围内。

## 替代方案

- Redis Pub/Sub 广播配置版本：引入可靠性、顺序和订阅恢复问题，首期收益不足。
- 配置中心或共享 Secret Manager：新增外部依赖，超出热加载恢复与验收范围。
- 数据库轮询：增加延迟和实例间短暂不一致。

## 后果

- 容器重启后可由数据库配置和挂载的运行时 key 文件恢复当前快照。
- 管理员保存、测试、回滚的语义只在单实例下保证一致。
- 未来横向扩容前必须先实现配置与 key 的原子广播和缓存失效。
