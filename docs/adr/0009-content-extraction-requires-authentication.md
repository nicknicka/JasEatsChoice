# 0009 — 内容提取接口必须登录，身份只认已验证的 JWT

## 背景

内容提取的接口此前在 Spring Security 里全部走 `permitAll`，用户身份来自请求头 `X-User-Id`——该请求头未经任何校验就会被优先采用，取不到时再回落成共享的 `test_user`。后果是：任意调用者可以带上别人的 userId 冒充其身份；所有匿名请求共享同一份内容源、提取结果和小红书登录态；`publishAsRecipe` 与 `verifyExtraction` 甚至完全不校验归属，知道 ID 就能操作他人数据。现有测试 `missingTokenFallsBackToSharedTestUser` 把匿名共享这一行为固化了下来。

## 决策

1. **`/v1/content-extraction/**` 一律要求登录。** 未登录返回 HTTP 401，由前端既有流程跳转登录。
2. **服务端身份只取已验证 JWT 中的 userId。** 不再信任请求头 `X-User-Id`，本期不提供匿名身份。
3. **取消 `test_user` 回落。** 取不到可信身份即视为未登录。
4. **写操作必须校验归属。** 删除、重提取、发布、验证都以 `ContentSource.userId` 为准校验，与既有的详情与修改口径保持一致。

## 替代方案

- **允许匿名，签发独立匿名身份**：能保留未登录体验，但要新增匿名身份的签发、生命周期、数据归属与清理机制，成本远高于本期收益。
- **保持 `permitAll`，仅在 controller 手工抛 401**：改动最小，但身份仍依赖可伪造的请求头，越权问题原样保留。
- **保留 `X-User-Id` 作为"与 JWT 一致的提示值"**：需要额外的比对逻辑，且没有任何调用方依赖它，直接移除更简单。

## 后果

- 前端登录后本来就会自动附带 `Authorization`，正常 Web 与桌面流程不受影响；未登录访问会拿到 401。
- 直连脚本，以及固化"缺失 token 回落共享用户"的测试，必须改写为断言 401。
- 小红书登录态随真实用户隔离，不再出现匿名用户之间互相覆盖登录态的情况。
