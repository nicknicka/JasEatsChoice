# 0008 — 公告 Embedding 在线切换：自动重建索引，维度变化拒绝

## 背景

公告 RAG 的 Embedding 配置（供应商、模型、地址、维度）此前只来自环境变量与配置文件，改动必须重建镜像并重启后端；管理端 AI 配置页只能在线切换对话模型，页面上明确写着"Embedding 模型与向量维度不在线切换"。代价是换一个 embedding 端点要走改 `.env`、重建镜像、重启容器、手工删 collection、触发重建索引五步。

而 Embedding 与对话模型的切换代价本质不同：换对话模型对历史数据没有影响；换 Embedding 模型会让已写入的向量失去意义——即使维度相同，不同模型的向量也不在同一空间（ADR-0006 已记录"向量模型或维度变化需要新建 collection 并全量重建"）。

## 决策

1. **Embedding 配置并入 AI 运行时配置**：与对话模型同一份快照、同一次激活、同一次回滚，沿用 ADR-0007 的单实例约束。
2. **Embedding 用独立的运行时密钥槽位**，与"当前激活对话供应商的 key"分开存放、分别轮换。
3. **激活流程固定为：校验 → 切换配置 → 自动重建索引 → 就绪**。校验包含连通性、一次真实 Embedding 调用，以及"新模型的实际维度与现有 collection 维度一致"。
4. **重建期间公告检索失败关闭**：进入「重建中」状态，明确告知暂不可用，绝不返回基于旧向量的检索结果。
5. **重建失败不回滚配置**：停在不可用状态并允许重试。旧向量已不在新模型的向量空间里，回滚配置并不能恢复检索能力，只会掩盖问题。
6. **维度不一致一律拒绝**，不自动新建 collection；新建 collection 仍走人工/运维流程。

## 替代方案

- **双 collection + 别名切换做到零中断**：放弃。需要额外的别名管理与切换原子性设计，首期收益不足；失败关闭已经能避免错答。
- **照常检索，用旧索引撑到重建完成**：放弃。返回的是看似合理、实际错误的公告，比暂时不可用更糟。
- **重建失败自动回滚配置**：放弃。回滚救不回检索，只会让管理员误以为已经恢复。
- **维度变化也自动重建 collection**：放弃。删除集合是不可逆动作，首期交给有意识的人执行。

## 后果

- 管理端 AI 配置页需要新增 Embedding 区块（供应商、模型、地址、维度、独立密钥），并取消"Embedding 不在线切换"的说明。
- 公告 RAG 状态新增「重建中」，管理端需要能看到重建进度与失败原因。
- 换 Embedding 端点/密钥（模型与维度不变）不需要重建索引，属于真正意义上的秒切。
- 公告量大时重建耗时线性增长，期间公告检索不可用——首期接受该行为。
