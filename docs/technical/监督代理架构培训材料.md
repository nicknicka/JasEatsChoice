## 课程大纲

### 第一部分：架构概览（30分钟）

#### 1.1 什么是监督代理模式？

**定义**: 监督代理（Supervisor Agent）是 L3 层级的智能代理，负责协调 L1/L2 Agent 完成复杂任务。

**三层架构**:
```
L3: SupervisorAgent (监督代理)
  ↓ 智能调度
L2: Domain Agents (领域代理)
  ↓ 工具调用
L1: Base Agents (基础代理) + Tools
```

**核心价值**:
- ✅ 自动路由：根据问题自动选择合适的 Agent
- ✅ 多Agent协作：协调多个 Agent 并行工作
- ✅ 状态共享：Agent 之间自动传递数据
- ✅ 错误恢复：处理 Agent 调用失败

#### 1.2 AgenticServices vs AiServices

| 特性 | AiServices | AgenticServices |
|------|-----------|-----------------|
| 构建器 | `.builder()` | `.agentBuilder()` / `.supervisorBuilder()` |
| 状态共享 | ❌ 不支持 | ✅ 支持（AgenticScope） |
| 监督代理 | ❌ 不支持 | ✅ 支持（SupervisorAgent） |
| 调用链监控 | ❌ 不支持 | ✅ 支持（AgentListener） |
| 适用场景 | 单一 Agent | 多 Agent 协作 |

#### 1.3 实际应用场景

**场景1：智能推荐**
```
用户: "推荐一些低卡路里的川菜"
↓
SupervisorAgent → SmartRecommendationAgent
→ 推荐菜品列表
```

**场景2：综合咨询**
```
用户: "我想减肥，推荐健康的菜并分析营养"
↓
SupervisorAgent
  → SmartRecommendationAgent (推荐菜品)
  → HealthManagementAgent (营养分析)
→ 综合回复
```

### 第二部分：核心概念（45分钟）

#### 2.1 AgenticScope 状态共享

**什么是 AgenticScope?**

AgenticScope 是 Agent 之间的状态共享机制，类似于"工作记忆"。

**使用方式**:

```java
// L1 Agent 配置输出键
AgenticServices.agentBuilder(NutritionGuideAgent.class)
    .outputKey("nutritionInfo")  // 配置输出键
    .build();

// L2 Agent 可以访问 L1 的输出
// 状态通过 AgenticScope 自动传递
```

**状态传递流程**:

```
L2 Agent 调用
  → LLM 决定调用 L1 Agent
  → L1 Agent 执行并返回结果
  → 结果自动传递给 L2 Agent
  → L2 Agent 综合处理
```

#### 2.2 监督代理的配置

**核心配置参数**:

```java
AgenticServices.supervisorBuilder(SupervisorAgent.class)
    .chatModel(chatModel)                              // ChatModel
    .chatMemoryProvider(memoryId -> chatMemory)        // ChatMemory提供者
    .name("SupervisorAgent")                           // 名称
    .supervisorContext("...")                          // 系统提示词
    .contextGenerationStrategy(CHAT_MEMORY_AND_SUMMARIZATION)  // 上下文策略
    .responseStrategy(SCORED)                          // 响应策略
    .maxAgentsInvocations(10)                          // 最大调用次数
    .build();
```

**上下文策略对比**:

| 策略 | 说明 | 适用场景 |
|------|------|----------|
| `CHAT_MEMORY` | 保留完整聊天历史 | 短对话（<10轮） |
| `SUMMARIZATION` | 自动摘要长对话 | 长对话（>50轮） |
| `CHAT_MEMORY_AND_SUMMARIZATION` | 混合策略 | **推荐** |

**响应策略对比**:

| 策略 | 说明 | 适用场景 |
|------|------|----------|
| `SCORED` | LLM 评分选择最佳 | **推荐** |
| `SUMMARY` | 生成摘要回复 | 需要简洁总结 |
| `LAST` | 使用最后一个响应 | 单 Agent 场景 |

#### 2.3 监控和可观测性

**监听器类型**:

1. **AgentCallTracer**: 调用链追踪
   - 记录 Agent 调用开始/结束
   - 记录工具调用
   - 生成调用链报告

2. **AgentPerformanceMonitor**: 性能监控
   - 统计总调用次数
   - 计算平均耗时
   - 记录最大耗时

**监控 API**:

```bash
# 性能统计
curl http://localhost:8080/api/admin/agent-monitoring/performance-stats

# 调用链报告
curl http://localhost:8080/api/admin/agent-monitoring/call-chain/session-1

# 监控概览
curl http://localhost:8080/api/admin/agent-monitoring/overview
```

### 第三部分：实战演练（45分钟）

#### 3.1 创建 L1 Agent

**步骤1**: 定义接口

```java
public interface NutritionGuideAgent {
    String chat(String userMessage);
}
```

**步骤2**: 配置 Bean

```java
@Bean
public NutritionGuideAgent nutritionGuideAgent(ChatModel chatModel, ChatMemory chatMemory) {
    return AgenticServices.agentBuilder(NutritionGuideAgent.class)
            .chatModel(chatModel)
            .chatMemory(chatMemory)
            .tools(nutritionAnalysisTools, calorieCalculatorTools)
            .outputKey("nutritionInfo")  // 状态共享
            .build();
}
```

#### 3.2 创建 SupervisorAgent

**步骤1**: 定义接口

```java
public interface SupervisorAgent {
    String chat(String userMessage);
    String chatWithContext(String userMessage, String userId);
}
```

**步骤2**: 配置 Bean

```java
@Bean
public SupervisorAgent supervisorAgent(ChatModel chatModel, ChatMemory chatMemory) {
    return AgenticServices
            .supervisorBuilder(SupervisorAgent.class)
            .chatModel(chatModel)
            .chatMemoryProvider(memoryId -> chatMemory)
            .supervisorContext("""
                # 角色定义
                你是一个智能监督代理...

                # 可用的领域专家Agent
                1. SmartRecommendationAgent - 智能推荐专家
                2. HealthManagementAgent - 健康管理专家
                """)
            .contextGenerationStrategy(
                SupervisorContextStrategy.CHAT_MEMORY_AND_SUMMARIZATION
            )
            .responseStrategy(SupervisorResponseStrategy.SCORED)
            .maxAgentsInvocations(10)
            .build();
}
```

#### 3.3 创建 Controller

```java
@RestController
@RequestMapping("/api/agent/supervisor")
public class SupervisorAgentController {

    @Resource
    private SupervisorAgent supervisorAgent;

    @PostMapping("/chat")
    public ResponseResult<String> chat(@RequestBody ChatRequest request) {
        String response = supervisorAgent.chat(request.getMessage());
        return ResponseResult.success(response);
    }
}
```

#### 3.4 测试验证

```bash
# 启动应用
./mvnw spring-boot:run

# 测试 API
curl -X POST http://localhost:8080/api/agent/supervisor/chat \
  -H "Content-Type: application/json" \
  -d '{"message": "推荐一些低卡路里的川菜"}'
```

## 常见问题

### Q1: 如何调试 Agent 调用链？

**A**: 使用监控 API 查看调用链报告

```bash
curl http://localhost:8080/api/admin/agent-monitoring/call-chain/session-1
```

报告中会显示：
- 调用了哪些 Agent
- 每个调用的耗时
- 工具调用记录

### Q2: Agent 调用失败怎么办？

**A**: SupervisorAgent 会自动处理失败：

1. 单个 Agent 失败不影响其他 Agent
2. 尽量使用成功的 Agent 结果
3. 明确告知用户部分功能不可用

### Q3: 如何提高 Agent 响应速度？

**A**: 优化建议：

1. **减少最大调用次数**: `.maxAgentsInvocations(5)`
2. **使用简单上下文策略**: `CHAT_MEMORY`
3. **优化工具查询**: 添加缓存
4. **调整 LLM 参数**: 降低 `temperature`

### Q4: 如何添加新的 L2 Agent？

**A**: 三个步骤：

1. 创建 Agent 接口
2. 配置 Bean（可以使用 `AiServices.builder()`）
3. 在 SupervisorAgent 的提示词中添加说明

## 最佳实践

### 1. Agent 职责单一

每个 Agent 只负责一个领域：

- ✅ `SmartRecommendationAgent` - 只负责推荐
- ✅ `HealthManagementAgent` - 只负责健康管理
- ❌ `AllInOneAgent` - 避免全能 Agent

### 2. 明确提示词

在 `supervisorContext` 中明确：

- Agent 的职责和能力边界
- Agent 之间的协作规则
- 输出格式要求

### 3. 监控性能

定期查看性能指标：

```bash
curl http://localhost:8080/api/admin/agent-monitoring/performance-stats
```

关注：
- 平均耗时 < 2秒
- P95 耗时 < 3秒
- 错误率 < 1%

### 4. 渐进式迁移

迁移顺序：

1. 先迁移 L1 Agent
2. 再实现 SupervisorAgent
3. 最后适配 Controller
