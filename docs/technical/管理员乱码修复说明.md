# 管理员乱码修复说明

## 背景
管理员截图中的中文乱码，已确认主要来自历史数据入库时的错误编码，而不是当前接口响应编码或页面渲染编码。

补充判断：

- 仓库中的建表迁移文件本身是正常中文。
- 当前数据库里仍有部分表注释、字段注释是乱码。
- 这说明问题更接近“早期执行 SQL 或导入数据时使用了错误连接编码”，而不是源码文件本身已损坏。

本次修复分为两部分：

- 数据修复：通过数据库迁移脚本修复命中典型乱码模式的历史字段。
- 页面收敛：移除管理员头部的局部猜测性兜底，并修正充值页与后端字段、枚举不一致的问题。

## 已落地内容

### 1. 数据修复迁移
- 文件：`JasEatsChoiceJava/src/main/resources/db/migration/V2026050401__repair_admin_mojibake_data.sql`
- 覆盖范围：
  - 用户昵称、所在地、简介
  - 菜品名称、描述、审核意见
  - 热点内容、备注、审核意见
  - 商家名称、地址、联系人、审核备注
  - 公告标题、公告内容
  - 角色描述
  - 权限名称、权限描述
  - 管理员姓名、备注
- 额外处理：
  - 按 `role_code` 将三类内置角色恢复为规范中文名称和描述，避免继续显示测试占位值。

### 2. 排查脚本
- 文件：`scripts/audit_admin_mojibake.py`
- 用途：
  - 扫描管理员相关表中的典型乱码
  - 输出原始值和修复预览
  - 汇总相关表注释、字段注释中的乱码数量

示例：

```bash
python3 scripts/audit_admin_mojibake.py
python3 scripts/audit_admin_mojibake.py --output output/reports/admin-mojibake-report.md
```

### 3. 前端收敛
- `AdminLayout.vue`
  - 不再用正则猜测角色名是否乱码
  - 优先按 `roleCode` 映射展示，未命中时再回退接口返回值
- `RechargeManagement.vue`
  - 修正充值方式、状态筛选值与后端实际枚举不一致的问题
  - 兼容 `id/rechargeId` 两种记录主键字段
  - 兼容详情接口返回 `{ success, data }` 的结构

### 4. 后端兼容
- `RechargeRecordServiceImpl`
  - 查询条件改为“有文本才拼接”，避免空字符串筛选值干扰查询

## 回归建议

优先检查以下管理页：

- 用户管理
- 菜品审核列表
- 菜品审核详情
- 热点话题管理
- 角色管理
- 权限管理
- 管理员顶部角色展示
- 充值记录页

验收标准：

- 中文字段直接可读
- 同一条记录在数据库、接口、页面三处一致
- 页面不再依赖单页局部乱码判断

## 当前遗留

- 管理端相关表注释、字段注释仍有历史乱码，已纳入排查脚本统计，但本次没有自动改写数据库元数据。
- 这部分不影响页面截图和业务接口返回值，后续如需统一修复，建议单独做一次数据库元数据整理。
