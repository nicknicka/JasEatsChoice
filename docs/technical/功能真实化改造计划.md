# 功能真实化改造计划（Mock → 真实实现）

> 生成日期：2026-10-27
> 依据：`docs/technical/假实现与接口对齐审计清单.md`
> 目标：把所有 mock/假成功/假数据功能，改造成真实、可靠、低耦合的实现；测试同步诚实化。

## 一、总原则

1. **测试先行**：先让测试"诚实"（不再假绿），再改功能；功能改完由测试验收。
2. **低耦合**：失败时统一"报错 + 空态"，禁止回填假数据；接口契约单一来源。
3. **已定决策**：
   - 支付**只保留平台币**；微信/支付宝**保留接口骨架但不实现**（无支付权限），前端入口隐藏或明确"暂未开放"。
   - 审计清单 A/B/C 里的**空壳功能一律补齐**（不删除）。
4. **不做**：线下收银、供应链仓储、第三方配送调度（项目已排除）。

## 二、主 issue 划分（6 个）

按"同一种修法 + 同一个决策 + 可独立交付验收"划分。规模排序：M1 > M4 > M2 > M3 > M5 > M6。

### M2. 前后端接口契约对齐

- **目标**：前端调用的每个接口路径/字段/值与后端一致，不再"调用即 404/字段读空"。
- **范围**（审计 C 节 12 项）：
  - 小程序：注册字段(M-01)、确认收货路径(M-02)、注册后续资料(M-03)、通知字段/值域(M-04/M-05)、收藏路由(M-06)、评价路由(M-07)、食谱搜索(M-08)、钱包字段/路径(M-09/M-10)
  - 桌面端：地址删除缺 userId(C-01)、管理员改密码路径(C-02)
- **验收**：
  - 12 项逐个修正，且每项有对应测试或手工验证记录
  - 全项目搜索无"调用了不存在路由"的死调用
- **依赖**：无（可与 M1 并行）
- **规模**：中。建议拆两个 PR：小程序端、桌面端。
- **标签**：`ready-for-agent`

### M3. 假成功修复：让操作真正生效

- **目标**：点击"删除/修改/加入"，结果真正落库；办不到就报错，绝不假报成功。
- **范围**：
  - **后端**（审计 B01/B07/B08/B11/B16/B17/B22/B23）：
    - 用户状态修改：补 User.status 字段 + 真正 update（或下架该功能入口，二选一，见开放项）
    - 提现失败/驳回：恢复 `walletService.refundWithdraw` 调用
    - 群订单消息同步/标记已同步：接 WebSocket 发送 + 补 synced 字段
    - 动态定时任务：反射调用真实任务，失败如实记 FAILED
    - 菜品状态/审核：检查 `updateById` 返回值，失败返回错误
  - **前端**（审计 F-A1~A7）：
    - 加入群订单、会话置顶、删订单（两处）、批量删菜单、标记已读：改为调真实 API
    - 图片/文件上传：接上传接口或隐藏入口
- **验收**：
  - 每个操作有集成验证：操作后**重新查询**，状态确实变化
  - 无一处在未落库时返回成功
- **依赖**：M1（红测先行）
- **规模**：中大。
- **标签**：`ready-for-agent`（用户状态"补齐 vs 下架"需先定）

- **标签**：`ready-for-agent`

### M5. 去除前端 Mock 降级与假数据

- **目标**：前端不再用假数据冒充真实数据；失败就显示空态/错误。
- **范围**（审计 F-B 类）：
  - 去掉"API 失败 → 回填 mock"的降级分支（推荐/教程/商家各页）
  - 死页面（F-C）：确认后删除小程序未注册旧页，或明确隔离
  - 初始写死数据（F-B15~B17、F-A9）：改为空初值 + 加载态
- **验收**：
  - 全项目搜索前端不应再有"失败时用模拟数据"路径
  - 断网/后端报错时，页面显示空态或错误提示，而非假数据
- **依赖**：M4（后端补齐后，前端无需降级）
- **规模**：中。
- **标签**：`ready-for-agent`

### M6. 支付收敛 + 死代码清理 + 文档失真修正

- **目标**：支付只剩平台币且明确；清理死代码；修掉误导性文档。
- **范围**：
  - **支付**（B13–B15、F-A8、F-A11）：
    - 后端 WechatPayService/AlipayPayService：**保留接口**，实现类改为明确"暂不支持"（抛业务异常或返回未启用），删除伪造 prepay_id/签名/验签逻辑
    - 前端：隐藏微信/支付宝支付入口，或点击提示"暂未开放"
    - 配置位保留并标注未启用；文档写明"无支付权限，不实现"
  - **死代码**：删除小程序未注册旧页（`pages/group-order/*` 等）、`coupon.example.js`、备份文件
  - **文档**：修正 PRD"用户注册未实现"、`implementation-plan.md`"100% 通过"等过期结论
- **验收**：
  - 全项目无假签名/假支付成功路径
  - 支付 UI 只出现平台币
  - 文档与真实状态一致
- **依赖**：可独立
- **规模**：中。
- **标签**：`ready-for-agent`

## 三、依赖与顺序

```
M1 测试诚实化 ──┬──> M3 假成功修复
                ├──> M4 空壳补齐 ──> M5 去前端 mock
                └──> （M6 支付部分）
M2 接口对齐 ──────（独立，可并行）
M6 清理 ──────────（独立，可随时做）
```

**执行顺序**：
1. **M1 + M2**（纯测试 / 纯契约，不碰业务逻辑，风险最低，可并行）
2. **M3 + M4**（功能真实化，红测驱动）
3. **M5**（前端去 mock，等 M4 后端就绪）
4. **M6**（清理收尾，随时可插）
