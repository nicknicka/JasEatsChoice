# 内容抓取技术实现

## 概述

内容抓取模块负责从外部平台（抖音、B站、小红书、快手、微信公众号、今日头条等）抓取视频/图文/文章内容，经 AI 识别后提取菜谱信息。

整个模块采用**三层架构 + 策略模式**设计：

```
用户提交URL
    ↓
┌─────────────────────────────────────────────┐
│  Layer 1: 内容抓取 (ContentFetcher)          │
│  根据平台和内容类型选择抓取策略，获取原始内容    │
└─────────────────────────────────────────────┘
    ↓
┌─────────────────────────────────────────────┐
│  Layer 2: AI识别 (ContentRecognizer)         │
│  将抓取到的内容交给 GLM-4V-Flash 视觉模型识别  │
└─────────────────────────────────────────────┘
    ↓
┌─────────────────────────────────────────────┐
│  Layer 3: 结果解析 (ResultParser)            │
│  解析 AI 返回的 JSON，写入数据库               │
└─────────────────────────────────────────────┘
```

## 整体架构

### 核心接口与类

| 类名 | 职责 |
|------|------|
| `ContentFetcher` | 抓取策略接口，定义 `canHandle()` 和 `fetch()` |
| `VideoContentFetcher` | 视频抓取策略（抖音/B站/快手/小红书） |
| `ArticleContentFetcher` | 文章/图文抓取策略（微信/小红书/头条/通用） |
| `ImageContentFetcher` | 图片抓取策略（直接下载图片转 Base64） |
| `ContentFetcherFactory` | 工厂类，根据 platform + contentType 自动路由到对应抓取器 |
| `GlmVisionRecognizer` | AI 识别器，调用 GLM-4V-Flash 进行菜谱识别 |
| `ContentExtractionServiceImpl` | 核心服务，编排三层流程 |

### 策略路由机制

```java
// ContentFetcherFactory 通过 Spring 自动注入所有 ContentFetcher 实现
public ContentFetcher getFetcher(ContentPlatform platform, ContentType contentType) {
    return fetchers.stream()
        .filter(f -> f.canHandle(platform, contentType))
        .findFirst()
        .orElse(兜底 -> ArticleContentFetcher);
}
```

## Layer 1: 内容抓取策略详解

### 1. 抖音视频

**文件**: `VideoContentFetcher.java` → `fetchDouyinVideo()`

**抓取流程**:
```
分享短链接 → Jsoup跟随重定向 → 获取真实URL
    → 正则提取视频ID (/video/7xxx 或 modal_id=xxx)
    → 拼接标准页面URL (douyin.com/video/{id})
    → 解析页面 meta 标签获取信息
```

**关键代码**:
```java
// 解析短链接重定向
String realUrl = resolveDouyinUrl(url);
// 提取视频ID
String videoId = extractDouyinVideoId(realUrl);
// 通过页面获取视频信息
return fetchVideoInfoFromPage("https://www.douyin.com/video/" + videoId, ...);
```

**局限性**: 抖音页面需要 JS 渲染，Jsoup 只能获取 meta 标签中的部分信息。

---

### 2. B站视频

**文件**: `VideoContentFetcher.java` → `fetchBilibiliVideo()`

**抓取流程**:
```
URL → 正则提取BV号 (BVxxxxxxxxxx)
    → 调用B站API获取视频信息 (/x/web-interface/view?bvid=xxx)
    → 调用B站API获取视频流地址 (/x/player/playurl?bvid=xxx&cid=xxx)
    → 返回标题、作者、描述、封面图、视频直链
```

**关键代码**:
```java
String apiUrl = "https://api.bilibili.com/x/web-interface/view?bvid=" + bvid;
String json = Jsoup.connect(apiUrl).ignoreContentType(true).execute().body();
// 解析返回的JSON
info.title = data.path("title").asText("");
info.coverUrl = data.path("pic").asText("");
// 获取视频流地址
String playUrl = "https://api.bilibili.com/x/player/playurl?bvid=" + bvid + "&cid=" + cid + "&qn=16&fnver=0&fnval=16";
info.videoUrl = playRoot.at("/data/dash/video/0/baseUrl").asText();
```

**优势**: B站有公开 API，不需要登录即可获取视频信息和流地址。`qn=16` 表示最低画质（360P），减小视频大小。

### 3. 小红书（核心重点）

**文件**: `VideoContentFetcher.java` → `fetchXiaohongshuVideo()`

这是最复杂的抓取策略，利用了小红书页面的 **SSR（服务端渲染）** 机制。

#### 3.1 技术原理

小红书虽然是 SPA（单页应用），但为了 SEO，在服务端渲染时会将完整的笔记数据以 JSON 格式嵌入 HTML 的 `<script>` 标签中：

```html
<script>window.__INITIAL_STATE__={"note":{"noteDetailMap":{"笔记ID":{"note":{完整笔记数据}}}}}</script>
```

这个 `__INITIAL_STATE__` 包含了笔记的标题、描述、图片列表、视频地址、作者信息等所有数据。

#### 3.2 抓取流程

```
原始URL（带 xsec_token）
    ↓
Jsoup 请求页面（模拟浏览器请求头）
    ↓
检查是否被重定向到 404（反爬拦截检测）
    ↓
方法1: 解析 __INITIAL_STATE__
    ├── 定位 <script> 标签中的 __INITIAL_STATE__
    ├── 提取等号后的 JSON 字符串
    ├── 处理 JavaScript undefined → 替换为 null
    ├── Jackson 解析 JSON
    ├── 按路径导航: note.noteDetailMap.<noteId>.note
    └── 提取: title / desc / imageList / video.media.stream / user.nickname
    ↓ (失败则降级)
方法2: 解析 og:meta 标签
    ├── og:title → 标题
    ├── og:description → 描述
    ├── og:image → 封面图
    └── og:video → 视频URL
    ↓ (再失败则降级)
方法3: <title> 标签兜底
    └── 去除 " - 小红书" 后缀
```

#### 3.3 关键技术点

**a) 必须使用原始 URL（带 xsec_token）**

```
❌ https://www.xiaohongshu.com/explore/6821ee990000000021008234
   → 被重定向到 404，错误码 300031 "当前笔记暂时无法浏览"

✅ https://www.xiaohongshu.com/discovery/item/6821ee990000000021008234
     ?xsec_token=ABz8JXmbngbsRtknMwcJkgva-xfid9LPMFi11x1EkdBe8=
   → 正常返回页面，包含完整 SSR 数据
```

**b) 处理 JavaScript `undefined` 字面量**

小红书 SSR 的 `__INITIAL_STATE__` 中混入了 JavaScript 的 `undefined`，这不是合法的 JSON 值：

```javascript
// 原始内容（不合法 JSON）
window.__INITIAL_STATE__={"key":undefined,"list":[undefined,123]}

// 替换后（合法 JSON）
window.__INITIAL_STATE__={"key":null,"list":[null,123]}
```

```java
jsonStr = jsonStr.replace(":undefined", ":null")
                 .replace(",undefined,", ",null,")
                 .replace("[undefined,", "[null,")
                 .replace(",undefined]", ",null]");
```

**c) 404 重定向检测**

小红书的反爬机制会将无法验证的请求重定向到 404 页面：

```java
if (finalUrl.contains("/404") || finalUrl.contains("error_code=")) {
    return null; // 标记为抓取失败
}
```

**d) 笔记 ID 提取**

支持两种 URL 格式：

```java
Pattern pattern = Pattern.compile("/(?:discovery/item|explore)/([a-f0-9]{24})");
```

- `/discovery/item/{24位十六进制ID}`
- `/explore/{24位十六进制ID}`

#### 3.4 JSON 数据结构

`__INITIAL_STATE__` 中笔记数据的关键路径：

```json
{
  "note": {
    "noteDetailMap": {
      "<笔记ID>": {
        "note": {
          "title": "标题",
          "desc": "描述",
          "user": { "nickname": "作者" },
          "imageList": [
            { "urlDefault": "图片URL", "url": "备选URL", "infoList": [...] }
          ],
          "video": {
            "media": {
              "stream": [
                { "masterUrl": "视频直链", "backupUrls": ["备选URL"] }
              ]
            },
            "cover": "视频封面"
          }
        }
      }
    }
  }
}
```

## Layer 2: AI 识别

**文件**: `GlmVisionRecognizer.java`

### 识别策略

| 输入内容 | 识别方式 | 调用路径 |
|---------|---------|---------|
| 视频 + 直链URL | 直接传视频URL给 GLM-4V | HTTP API（绕过 LangChain4j） |
| 图片 + 文字 | 图片Base64 + 文字prompt | LangChain4j visionModel |
| 封面图降级 | 封面图URL + prompt | LangChain4j visionModel |
| 仅文字 | 文字prompt | LangChain4j agentModel |
| 无内容 | URL关键词推断 | LangChain4j agentModel |

### 为什么视频绕过 LangChain4j

LangChain4j 的智谱 AI 适配器只处理 `TextContent` 和 `ImageContent`，不处理 `VideoContent`。因此视频识别直接调用智谱 HTTP API：

```java
// 直接构造 HTTP 请求
HttpHeaders headers = new HttpHeaders();
headers.set("Authorization", "Bearer " + apiKey);
requestBody.put("model", "glm-4v-flash");
requestBody.put("messages", [{ video_url + text prompt }]);
```

### AI 识别返回格式

```json
{
  "isRecipe": true,
  "dishName": "番茄炒蛋",
  "description": "经典家常菜",
  "ingredients": [{"name": "番茄", "amount": "2个"}],
  "steps": [{"stepNumber": 1, "description": "番茄切块"}],
  "cookingTime": 15,
  "difficulty": "简单",
  "tags": ["家常菜", "快手菜"],
  "calories": 200
}
```

AI 返回的内容可能包含 markdown 代码块，需要先提取纯 JSON：

// 优先级：```json ``` > ``` ``` > 裸JSON对象

## 降级与容错策略

### 抓取层降级链

```
平台专用API（如B站API）
    ↓ 失败
页面 SSR 数据解析（如小红书 __INITIAL_STATE__）
    ↓ 失败
og:meta 标签解析
    ↓ 失败
<title> 标签 + 页面正文提取
    ↓ 失败
返回 fetchSuccess=false
```

### 识别层降级链

```
视频 + 文字 → GLM-4V 视频理解
    ↓ 失败
图片 + 文字 → GLM-4V 图像识别
    ↓ 失败（有封面图）
封面图 → GLM-4V 图像识别
    ↓ 失败（有文字）
纯文字 → GLM-4 文本提取
    ↓ 失败（无内容）
URL 关键词推断 → GLM-4 文本生成
```

### 任务重试机制

- 最多重试 3 次（`MAX_RETRY_COUNT = 3`）
- 每次重试创建新的 ExtractionTask
- 超过重试次数标记为 FAILED

## 配置与依赖

### 技术栈

| 技术 | 用途 |
|------|------|
| Jsoup | HTTP 请求 + HTML 解析 |
| Jackson | JSON 解析（`__INITIAL_STATE__`、B站API响应） |
| LangChain4j | AI 模型调用（图片+文字识别） |
| RestTemplate | 直接 HTTP 调用（视频识别绕过 LangChain4j） |
| GLM-4V-Flash | 智谱视觉模型（图片+视频理解） |
| GLM-4 | 智谱文本模型（降级文本识别） |

### 模型配置

在 `ZhipuAIConfig` 中配置：

```yaml
zhipu:
  api-key: xxx
  base-url: https://open.bigmodel.cn/api/paas/v4/chat/completions
  vision-model: glm-4v-flash  # 视觉模型（图片+视频）
  agent-model: glm-4-flash     # 文本模型（降级）
```

## 已知限制与改进方向

### 当前限制

| 问题 | 影响 | 平台 |
|------|------|------|
| 抖音页面需 JS 渲染 | Jsoup 无法获取完整信息 | 抖音 |
| 快手无专用 API | 只能获取 meta 标签信息 | 快手 |
| 小红书 SSR 数据可能变更 | `__INITIAL_STATE__` 结构改变会导致解析失败 | 小红书 |
| 视频直链有时效性 | 视频 URL 可能过期 | B站 |
| 反爬机制 | 请求可能被拦截 | 所有平台 |

### 改进方向

1. **引入 Playwright/Selenium 无头浏览器** — 解决 JS 渲染问题，适用于抖音、快手
2. **使用第三方 API 服务** — 如 RapidAPI 上的社交平台内容抓取 API，更稳定
3. **缓存视频直链** — 避免重复请求
4. **Cookie 池管理** — 轮换请求身份，降低被拦截概率
5. **小红书 Web API 签名** — 通过逆向获取 `X-s`/`X-t` 签名算法，直接调用 API
