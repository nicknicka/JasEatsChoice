## 这页在讲什么
顶部三个审核进度数字（待审核/今日已审核/本周通过率）加一张待审商家表，回答"还有谁等着我批"。

## 主角 / 主动作
- 主角是待审核列表，主动作是逐行"通过 / 拒绝"。
- 通过（绿文字）与拒绝（红文字）并列，是本页最重的操作，位置在最右侧列，符合阅读终点，方向对。
- 建议给"拒绝"加二次确认或行内确认，因为拒绝是破坏性动作，当前与"通过"仅靠颜色区分，误触即生效。

## 层级与构图
- 概览三卡等宽居中，数量少但留白匀，构图干净。
- 内容卡表头"待审核商家列表"左 + 刷新按钮右，是本项目列表页里表头动作放得最规范的一处，可作为基准。
- "商家ID"列同样过窄，seedm20260520_03 被折成两行，切断了标识。
- 分页条 "Total 0" 却显示 8 行数据，数字与内容互相矛盾，是明显的状态表达错误。

## 色彩与字体
- 操作列用绿色"通过"、红色"拒绝"，颜色语义正确。
- 概览三卡纯数字，无色差，待审核 0 与本周通过率 0% 视觉等价，看不出哪个是待办入口。
- 表内无金额，未出现衬线数字问题。

## 留白与节奏
- 概览区、表头、表格之间纵向间距一致，节奏稳。
- 表格行高仍受"商家ID"两行折行影响，行高不齐。
- 卡底分页区与表格之间有独立分隔，层次可读。

## 动效与交互反馈
- 刷新按钮无 loading/旋转反馈，点击后没有任何进行中状态。
- 通过/拒绝点击后是否成功仅靠下一次数据刷新确认，缺少局部结果反馈（行移除/出现）。
- 表格行无 hover 高亮。

## 与相邻页的一致性
- 与 03-商家管理 是同域的列表页，但 03 有独立筛选卡、04 把刷新放进内容卡表头，两页的表头/筛选处理不一致。
- 与 02/03 相比，本页操作收敛成两个文字链接，是更克制的做法，建议反向统一其他列表页。
- "Total 0" 与实际行数矛盾的问题同样出现在 11-公告管理、13-充值记录，属跨页共性缺陷。

- P0 必改：拒绝动作加二次确认，并让成功/失败有即时行内反馈。
- P1 建议：概览卡给"待审核"一个统一待办强调色。
