# 退款管理（admin/14-refunds）

- 截图：output/web-screenshots/admin/14-refunds.png
- URL：/admin/finance/refunds
- 评审人：review-admin

## 这页在讲什么
顶部四个退款口径（待处理/今日已退/今日已拒/本月退款总额），下方退款明细表回答"哪些订单申请退款、原因是什么、批到哪一步"。

## 主角 / 主动作
- 主角是退款表，主动作是"处理待处理退款 / 查看详情"。
- 行操作默认只有灰色"详情"，仅"待处理"行多出一个蓝色"处理"。主动作只在特定行出现，容易被忽略；建议对待处理行用更醒目的主色，并对其他行统一为同一层次。

## 层级与构图
- 概览"纯数字居中"四卡，与 03/05/06/13/21 同源。
- 筛选区：第一行 关键词/退款状态/申请日期 + 搜索/重置，折成两行，第二行只有搜索/重置，右侧空。
- "退款ID"列过窄，RFDSEED20260520_10 被折成两行，切断标识。
- "申请时间"展示原始时间戳 2026-05-20T09:45:00，带 T。

## 色彩与字体
- 退款金额（¥54、¥21…）红色粗体衬线，红色对退款金额语义勉强，但衬线数字与正文不同族。
- 状态标签覆盖 已拒绝（浅红）、已完成（绿）、退款中（灰）、已批准（浅紫蓝）、待处理（橙），五种色相混排，色板偏杂。
- "详情"用灰色文字，视觉上像禁用态，与"处理"的蓝形成"可点/不可点"的错误暗示。

## 留白与节奏
- 表格行高被"退款ID"折行撑高，部分行两行高、部分单行，节奏不齐。
- 概览—筛选—表格三段间距一致。
- 筛选第二行留白偏多。

## 动效与交互反馈
- "处理"进入后续流程无过渡；处理完成后无行内结果反馈（行状态是否即时变化不明）。
- 表格行无 hover 高亮。
- 概览数字无变化过渡。

## 与相邻页的一致性
- 概览卡与 13-充值记录 同源，两页同属财务、构图一致，是正面一致的例子（但与 12-提现审核 仍不同源）。
- 金额红色、时间戳带 T、ID 折行与 05/06/12/13 同病。
- 状态标签色板比 05/06/13 更杂，需并入统一状态色。

- P0 必改：申请时间格式化为 "2026-05-20 09:45"。
