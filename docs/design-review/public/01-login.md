# 登录（public/01-login）

- 截图：output/web-screenshots/public/01-login.png
- URL：/login
- 评审人：review-public

## 这页在讲什么
一个把品牌放在最上面、用暖橙渐变垫底的单列登录页：顶部交代「佳食宜选」是谁，下面一次性把手机号／密码／验证码填完，再点满宽的橙色主按钮进来。

## 主角 / 主动作
- 主角是登录表单本身，唯一主动作是「登录」按钮。
- 现状：输入框与按钮横跨 x=20→1419（视口 1440 的约 97%），主动作被拉成一条约 1400×41 的橙色带，靠面积而不是位置拿权重；「手机号 → 密码 → 验证码 → 登录」的视线要横向跨整屏才能串起来。
- 同权重动作：微信／QQ 登录（两个无文字的圆形图标，贴底 y≈809）、「立即注册」（底部 y≈861）、「忘记密码?」（表单右侧 y≈364）。社交登录与「立即注册」当前被拆到页面底部、与主动作等距分散，应合并进同一列并降到从属位置。

## 层级与构图
- 缺列宽约束：表单、按钮都拉到近全宽，单列约 1400px，不符合登录表单「窄列居中」的通行做法（同类产品登录列普遍在 360–420px）。
- 页面被切成三段且互不相接：品牌区（y≈55–155）／表单区（y≈205–458）／社交登录+注册入口（y≈777–875）。
- 品牌区与表单区之间没有卡片或分隔线，表单块直接铺在渐变背景上，缺可识别的容器边界。
- 验证码输入框占满约 1300px 宽却只放 3 位数字（截图内为「531」），宽度与内容量完全不匹配。
- 一页混用两套对齐基准：品牌区居中、表单左对齐到 x=20、社交图标居中、底部文字居中。

## 色彩与字体
- 主色橙 (237,106,66) 用在「登录」按钮，与顶部渐变偏橙 (238,159,130) 呼应，基调统一。
- 品牌字标「佳食宜选」约 24px 深棕，副标「美食由你选择」约 13px 灰棕；辅助链接与勾选文案 12–13px，在 1400 宽度下整体偏细偏小。
- 《用户协议》《隐私政策》用主色橙作链接色，与整体一致，保留。

## 留白与节奏
- 节奏呈「上紧、中空、下散」：品牌区与表单贴合；主按钮下方到社交分隔线（y≈458→777）约 320px 纯空；随后社交登录与注册入口贴着底边（y≈777–875）。
- 表单内字段间距约 7–8px，偏紧，与下方 320px 大空档反差过大，视线落点被拉断。

## 动效与交互反馈
- 静态截图无法验证动效；结构上缺以下反馈位：输入框聚焦态、社交图标 hover 与键盘焦点态、验证码刷新（右侧圆形图标）反馈、主按钮 loading 与未勾选协议时的不可点态、切换到「立即注册／忘记密码」的过渡。
- 「我已阅读并同意」未勾选时「登录」按钮应降级，这一联动在当前画面看不出，需交互验证。

## 与相邻页的一致性
- 与 02-register、03-forgot-password 属同一套：共享暖色基调与「全宽字段 + 全宽实心橙按钮」语法，批内自洽。
- 与 04-merchant-register 完全不一致（对方是绿底白卡 + 蓝色按钮 + 衬线标题），公共端内部存在两套视觉语言。

## 改造建议
- P0 必改：给表单列设宽度上限（建议 360–420px）并水平居中，手机号／密码／验证码输入框与「登录」按钮统一到该列宽；渐变背景保留。把主按钮从约 1400px 收敛到列宽。
- P0 必改：消除主按钮下方约 320px 空档——社交登录与「立即注册」收进同一列、紧跟按钮（间距 ≤ 32px），不再贴底分散。
- P1 建议：品牌区与表单列共用同一中轴（统一居中列），消除左对齐与居中混用。
- P1 建议：辅助文案与链接字号下限提到 ≥13px；「记住密码」与「忘记密码?」保持同行左右分布即可。
- P2 可选：验证码输入框按内容收窄，不再占满整列。
