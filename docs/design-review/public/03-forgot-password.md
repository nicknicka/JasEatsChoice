## 这页在讲什么
找回密码的第一步：用「重置密码」标题和两步进度条说明当前进度，靠验证手机号往下一步推进。

## 主角 / 主动作
- 主角是「验证手机号」表单，主动作是「下一步」。
- 现状：手机号与短信验证码输入框横跨 x=21→约 1310，占近全宽；「下一步」按钮 x=20→1419（约 1400×41），主动作靠面积而非位置拿权重。
- 次要动作「获取验证码」是橙色描边按钮（x=1329→1419，约 90×40），与实心主按钮形成主/次对比，层级成立，保留；「返回登录」贴底（y≈861）属三次要。

## 层级与构图
- 与 01/02 同样缺列宽约束，单列约 1300px，验证码字段被拉成长条。
- 进度条只有第一步「验证手机号」带标签，第二步为空圈无标签，无法预知后续。
- 页面三块分布：标题+进度条（y≈55–165）／表单（y≈213–350）／底部返回入口（y≈861），中段大空。
- 表单左对齐到 x=21，标题与进度条居中，两套基准混用。

## 色彩与字体
- 沿用暖色基调；主色橙用于「下一步」实心按钮，描边橙用于「获取验证码」，同一主色的两种强度，状态区分清楚。
- 标题约 22–24px；输入占位与辅助文字约 13px 偏小。
- 「获取验证码」约 40px 高，与输入框同高，行内对齐整齐，保留。

## 留白与节奏
- 表单下方（y≈350）到底部入口（y≈861）约 510px 空白，是 01/02/03 三页里最空的一张。
- 字段间距约 9–10px，偏紧，与大空档反差过大。

## 动效与交互反馈
- 静态截图无法验证动效；结构上缺：「获取验证码」点击后的倒计时与禁用态、验证码发送结果提示、「下一步」按钮 loading、步骤 1→2 过渡、手机号格式校验反馈位。
- 「获取验证码」当前看不出是否已实现倒计时，需交互验证。

## 与相邻页的一致性
- 与 01/02 同一暖色 + 全宽语法，批内自洽；进度条语法与 02 完全一致（「1 激活 + 2 空圈无标签」）。
- 与 04 绿底白卡蓝按钮割裂。

## 改造建议
- P0 必改：表单列设宽度上限（建议 360–420px）并居中，手机号、短信验证码字段与「下一步」统一列宽。
- P0 必改：给进度条第二步补文字标签，与 02 对齐，两步各有标签。
- P1 建议：底部「返回登录」收进同一列、紧跟表单，消除约 510px 空档。
- P1 建议：「获取验证码」补齐倒计时与禁用态、发送结果提示等可见状态。
- P2 可选：统一标题区与表单的对齐基准。
