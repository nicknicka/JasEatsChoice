# 菜品编辑（merchant/08-dish-edit）

- 截图：output/web-screenshots/merchant/08-dish-edit.png
- URL：/merchant/home/dish-edit
- 评审人：review-merchant

## 这页在讲什么
这页负责让商家录入菜品图片、名称、分类、价格、库存、描述与食材；当前表单以单列窄宽度堆在左侧，卡片右侧近一半宽度始终空白，页面看起来像没写完。

## 主角 / 主动作
主角是菜品基本信息表单，主动作是保存菜品。页面底部没有可见的保存按钮，首屏结束时停在“总卡路里”一行，商家拿不到完成录入后的下一步动作。

## 层级与构图
- 页面标题“【菜品编辑】”是页面左上角一段无卡片的粗体文字，“返回”是它下面的蓝色文字链接，与 04/07/10 的标题卡、02/03/05/11 的标题条都不属同一体系。
- “菜品图片”卡约 220px 高，虚线上传框约 150×150px 固定在左侧，右侧 850px 全部留白。
- “菜品基本信息”卡内所有控件左对齐、宽度约 300–500px，价格与库存用步进器（− 18 + 元 / − 50 + 份），描述用约 500×98px 文本域；卡片右半部分依旧空白。
- “总卡路里：0 kcal”以红色文字贴着卡片下沿，位置像被截断的字段，缺少与价格、库存同级的排版。
- 建议：图片上传区与基本信息改成左右两栏；价格、库存、卡路里并为一行；卡片宽度铺满；底部固定一条保存操作栏。

## 色彩与字体
- 字段标签前带 emoji（📝🗂️💰📦✏️📅），上传框内是灰色“+”号，正文“食材/价格”等说明使用浅灰，整体灰度偏平。
- “添加”按钮用蓝色实心，是页面里最饱和的元素，但真正的保存动作不可见，视觉权重分配与任务优先级相反。
- 价格与库存的步进器“+/−”按钮是浅灰描边，和输入框边界接近，可点区域不明显。
- “总卡路里：0 kcal”用红色，容易被读成校验错误或超出范围，而它只是当前值；建议改为中性色，只有超限时才变红。

## 留白与节奏
- 两张卡片各有一整块约 700–850px 宽的空白区，是页面视觉重心所在，实际内容全部挤在左三分之一。
- 卡片之间约 30px 间距、卡内字段间距稳定，但因为内容过窄，纵向节奏被拉长，首屏在“总卡路里”处被切断。
- 建议：用两列栅格把图片与基本信息并排，字段区按“标识信息 / 价格库存 / 描述 / 食材”分组，整页高度至少减少三分之一。

## 动效与交互反馈
- 静态截图无法验证图片上传、食材添加与保存。当前没有必填校验、上传进度或保存结果反馈。
- 建议：图片上传显示进度与可删除缩略图；食材“添加”后以 180ms 滑入 chip；保存按钮固定底部并在提交时 loading，成功给出 Toast；未通过校验的字段用红色边框加文字说明，而不是仅变色。

## 与相邻页的一致性
- 与 06“菜单编辑”同为编辑表单，但 06 有渐变标题条、08 没有标题容器，两者应共用同一套页面头、栅格和底部操作栏。
- emoji 字段标签、蓝色“添加”按钮与 06/07 同源，需一并替换为线性图标和统一主色。
- 食材录入在 07 用彩色 chip 展示、在本页用纯文本输入，两页的字段形态需要对齐。

## 改造建议
- P0 必改：把图片与基本信息改成两栏铺满卡片，底部补上保存操作栏；“总卡路里”改中性色。
- P1 建议：统一标题容器，替换 emoji 标签，给必填项与校验状态明确样式。
- P2 可选：加入图片上传进度、食材 chip 滑入与保存 loading/Toast。
