# 菜品管理（merchant/07-dish-management）

- 截图：output/web-screenshots/merchant/07-dish-management.png
- URL：/merchant/home/dish-management
- 评审人：review-merchant

## 这页在讲什么
这页负责让商家浏览菜品、查看上架状态与食材配置并批量改状态；当前每张菜品卡高达约 430px，900px 首屏只能看到一张半菜品，浏览与比较的基本诉求被卡片高度挡住。

## 主角 / 主动作
主角是菜品列表与单菜的“编辑/上下架”，主动作是编辑单道菜品。顶部“新增菜品”使用了低对比浅绿按钮，行内四个操作“下架/编辑/菜单关联/删除”全部是同款浅蓝白描边按钮，主次完全不分，删除也没有视觉隔离。

## 层级与构图
- 标题卡用“【菜品管理】”方括号写法，与 02/03/05/10 的写法不同；搜索框与“新增菜品”同处一行，按钮对比度低于搜索框边框，主动作被削弱。
- 工具条把“全选”与“批量上架/批量下架/批量删除”放同一行，三个批量按钮在未选中任何菜品时已经高亮，选择态与可操作态脱节。
- 菜品卡内字段用“分类/价格/库存/更新时间”四列平铺，本可压成一行；但下方“必选食材/可选食材/营养成分”各自另起一行并配一长串 chip，把卡片撑到约 430px。
- 食材 chip 直接显示“12 / 3 / 2 / 1 / 11 / 1 / 111 / 2”这类无意义占位数字，用户无法判断它代表食材名、数量还是序号。
- 建议：把食材与营养成分折叠为可展开的摘要行，卡片默认高度控制在 120–160px；字段行改为紧凑标签+值；删除按钮移到卡右侧或更多菜单中并与其余操作保持间距。

## 色彩与字体
- 批量上架为绿、批量下架为浅黄、批量删除为浅粉，三个按钮在禁用/空选状态下仍有颜色，红色语义被淡化。
- 行内“下架/编辑/菜单关联/删除”几乎同一浅蓝，删除与编辑同色，危险动作没有任何区分。
- 占位食材 chip 用浅粉底红字，营养成分“450 kcal”用橙色 pill，颜色数量超过信息层级需要，视觉噪声高于内容价值。
- 建议：批量按钮默认降为描边灰，选中后再上色；删除单独使用危险色且与其它操作留出间距；食材 chip 统一一种中性样式。

## 留白与节奏
- 标题卡约 105px、工具条约 90px，第一张菜品卡从 y≈258 开始并延伸到 y≈690，第二张卡在 y≈715 才开始，首屏几乎被一张卡占满。
- 菜品卡内部“字段行—分隔线—食材—分隔线—营养成分—按钮”五段均等分布，段间留白大于信息量，节奏被拉长。
- 建议：压缩字段区为两行、把食材/营养折叠，按钮固定到卡片底部一行；整卡高度减半后可一屏看到 3–4 道菜。

## 动效与交互反馈
- 静态截图无法验证批量选择、上下架和删除确认。食材 chip 的粉色与右侧操作按钮同为浅色系，hover 与选中态难以预判。
- 建议：勾选后用 180–220ms 滑入批量操作条；上下架切换原位更新状态标签，不做整卡重排；删除使用二次确认弹窗并给出可撤销提示。

## 与相邻页的一致性
- 与 04“菜单管理”是同一套“标题+工具条+卡片列表”的骨架，但卡片高度、按钮颜色与标题写法都不同，应共享同一套列表与批量操作规范。
- 食材/营养的 chip 语言在 06/08 没有对应，属于本页独立发明，需与编辑页的食材录入统一。
- “新增菜品”的浅绿按钮与 04“新增菜单”的绿色实心按钮不一致。

## 改造建议
- P0 必改：压缩菜品卡高度，让首屏能看到 3 道以上菜品；把删除从同色按钮中分离。
- P1 建议：统一标题写法与 04 对齐，修掉无意义的食材占位数字，批量按钮默认降级。
- P2 可选：加入批量条展开、上下架原位更新与删除二次确认动效。
