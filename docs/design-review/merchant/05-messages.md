# 商家消息管理（merchant/05-messages）

- 截图：output/web-screenshots/merchant/05-messages.png
- URL：/merchant/home/messages
- 评审人：review-merchant

## 这页在讲什么
这页负责让商家按分类查看系统、订单、评价消息并批量处理未读；当前画面把五个全为 0 的统计块放在最上方，真正需要看的消息列表只剩一片空白，页面在讲统计，而不是消息。

## 主角 / 主动作
主角应是消息列表，主动作应是“阅读/回复单条消息”。页面当前最重的是五张统计卡和一条四按钮工具条，“批量管理/全部标记为已读”在没有消息时仍是高亮主按钮，主动作指向了不存在的对象。

## 层级与构图
- 顶部绿色标题条内放入“消息中心”标题、副标题、搜索框和一个“返回”按钮；搜索属于列表工具，和页面级返回同权，位置不合理。
- 五张统计卡横跨整行，第一张“总消息”用深绿外框、其余四张各自用红/黄/蓝/绿左侧色条，一行里出现五套颜色，无法读出优先级。
- 分类卡片把筛选 chip 与“批量管理/全部标记为已读/刷新/导出”四个按钮塞进同一张约 190px 高的卡；按钮里蓝色“批量管理”和绿色“全部标记为已读”权重最高，可消息为 0 时两者都不可用。
- 空状态插图落在 y≈700、文案“暂无消息”在 y≈840，卡外大片背景空白，空状态没有居中在筛选区下方的可视区域。
- 建议：0 条时隐藏统计卡和批量按钮，只保留分类 chip 与居中空状态；有数据时把搜索移进分类工具条，把“全部标记为已读”降为次级按钮。

## 色彩与字体
- 五张 KPI 卡分别用绿、红、黄、蓝、绿做左侧色条，同一行内没有可解释的语义，红色“未读消息”在最左第二张尤其像告警。
- 绿色标题条使用深绿底白字，是本页最强的色块；正文按钮却混用蓝、绿、灰，主色语义仍不统一。
- 卡内标题 14px、数字 18px、副标题 12px 层级可读，但五张卡的图标底和色条让视线先落在颜色而不是数字。
- 建议：KPI 卡统一为一种底色，语义色只用在小图标上；主操作统一品牌色，次操作统一描边样式。

## 留白与节奏
- 标题条、KPI 区、分类卡之间各留约 20px，间距稳定；但三段合计约 480px，首屏下半部分完全交给空白。
- 五张 KPI 横向拉伸后数字与文字被分隔很远，单张卡内空余大于内容。
- 建议 0 条时把总高度压到约 260px，把空状态提到 y≈400 附近；有数据时再展开统计与工具条。

## 动效与交互反馈
- 静态截图无法验证分类切换、标记已读和批量选择。当前批量按钮即使在 0 条时也呈可用外观，没有禁用反馈。
- 建议：分类 chip 切换 160ms 过渡；标记已读后该行以 200ms 淡出并原位塌陷；批量条在勾选后才滑入；按钮 disabled 态明确降低对比度并保留可读文字。

## 与相邻页的一致性
- 与 12“评价中心”、14“教程管理”同为“统计块 + 列表”结构，但 KPI 卡样式、颜色和高度三页都不一样，应统一为一套统计组件。
- 分类 chip 的形态与 02/03 订单筛选、12 评价筛选接近，可共用同一套 chip 规范。
- 本页用深绿标题条，04/07/10 用白色标题卡，跨页头部语言不一致。

## 改造建议
- P0 必改：0 条时收起统计与批量操作，把“暂无消息”提到筛选区正下方居中；修复五张 KPI 卡的配色混乱。
- P1 建议：把搜索移入列表工具条，统一头部样式与按钮层级，红色只保留给真正的告警语义。
- P2 可选：加入分类切换过渡、标记已读原位淡出和按钮 disabled 反馈。
