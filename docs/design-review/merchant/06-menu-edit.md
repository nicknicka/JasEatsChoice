## 这页在讲什么
这页负责让商家填写菜单名称、上架时间、状态和描述，并挂载菜品后保存；当前表单只占了每张卡左侧约三分之一，右侧大片留白，页面看起来像被截断的表单。

## 主角 / 主动作
主角是“菜单基本信息”表单，主动作是页面底部三选一的保存动作。三个保存按钮“保存菜单并上架/保存菜单并下架/保存为草稿”同权并排，商家需要在三个近似动作里判断差异，主动作没有唯一答案。

## 层级与构图
- 顶部标题条用浅绿到深绿的横向渐变，与 02/03/05 的纯深绿标题条不一致，渐变在右侧变深后把“编辑菜单”标题衬得更淡。
- “菜单基本信息”卡约占 430px 高、“菜品管理”卡约 175px 高，两张卡宽度相同但内容密度差很大，第二张卡内只有两个按钮和一大片空。
- 表单控件固定约 300px 宽（名称、时间、状态下拉、描述框），在 1180px 的卡内全部左对齐，右半部分始终空白。
- 描述文本域约 490×98px，比上面的单行输入明显放大，但没有与之配套的字段分组或两列布局。
- 建议：表单改为两列栅格（名称/状态一行，上架/下架时间一行，描述占满宽度），把第二张卡的内容补齐或与第一张合并，三选一保存动作收敛为一个主按钮加“更多”。

## 色彩与字体
- 三个保存按钮分别用绿、橙、灰：橙色“保存菜单并下架”在通用认知里偏向警示，却和“保存为草稿”一样只是状态结果，语义冲突。
- 字段标签前全部使用 emoji（📝📅🕐⇄✏️📋），与 04/07/08 的 emoji 标签一致，但和备注、必填星号等正式表单元素混在一起，显得随意。
- 区块标题 18px 加粗、字段标签 14px，字号层级可用；描述框内的 placeholder 与被禁用输入框灰度接近，难以区分“空”与“不可编辑”。
- 建议：保存动作只保留一个主色按钮，其余放入下拉或次级按钮；用统一的线性图标替换 emoji；为必填项加明确标记。

## 留白与节奏
- 第一张卡内表单只占左侧三分之一，右下角留白约 700×250px，第二张卡留白约 700×80px，两处空白是页面最显眼的区域。
- 卡内标签与输入之间有稳定间距，节奏本身可控；问题在于内容被固定宽度挤到一边，无法利用卡片宽度。
- 建议按两列布局重新分配表单宽度，让每张卡的内容铺满，缩短整页高度，减少首屏必须滚动的距离。

## 动效与交互反馈
- 静态截图无法验证时间选择器、状态下拉和保存结果。当前没有必填校验、保存中或保存成功的可见线索。
- 建议：保存按钮点击后进入 300–400ms loading 并在成功时给出 Toast；日期/时间选择器与原输入框保持同一圆角与焦点环；三个保存动作差异用一句话副标题说明，而不是靠颜色区分。

## 与相邻页的一致性
- 与 08“菜品编辑”同为左右留白的编辑表单，但 08 没有标题卡、06 有渐变标题条，两者应共享同一套页面头与表单栅格。
- 保存按钮的三色组合与 04 的行内操作按钮颜色体系重叠，却没有共享规则。
- 区块标题、字段标签的 emoji 用法与 07/08 一致，应一并收敛。

## 改造建议
- P0 必改：把表单改为两列布局铺满卡片，收回右侧大面积留白；把三个保存动作收敛为“一个主按钮 + 次级选择”。
- P1 建议：统一标题条样式与 02/03/05 对齐，替换 emoji 标签并补必填标记。
- P2 可选：加入保存 loading、成功 Toast 和输入焦点统一反馈。
