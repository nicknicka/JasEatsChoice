# AI经营助手（merchant/16-ai）

- 截图：output/web-screenshots/merchant/16-ai.png
- URL：/merchant/home/ai
- 评审人：review-merchant

## 这页在讲什么
这页负责让商家用自然语言问经营问题并查看助手返回的数据卡片；当前助手消息被挤在对话区左侧一条约 300px 宽的窄列里，右侧近 700px 全部空白，回答区域严重失衡。

## 主角 / 主动作
主角是助手回答与输入框，主动作是输入问题并发送。输入框在页面底部横跨对话区，方向正确；但右下角“发送”按钮是浅色低对比外观，与“清空”几乎同权，主动作不够明确。

## 层级与构图
- 顶部为圆角卡：绿色“AI”方块 + “经营助手”标题 + “智能分析·高效运营”副标题，右侧绿色圆点“在线服务中”胶囊。信息完整，状态胶囊位置合理。
- 第二行为四个 Tab（经营助手/经营洞察/评价回复/菜品描述），选中项“经营助手”用白底描边胶囊，其余为纯文字。
- 对话主卡为白色大卡，内部有一条可滚动的消息区；助手返回的是三张订单卡（第18/19/20单，#ID 编号，已取消，菜品数量 1 道，总金额 ¥75），被限制在左侧窄列内。
- 消息区顶部第一张订单卡已被裁切（只露出下半截），说明滚动区域起始位置没有对齐到内容顶部。
- 订单卡内“第18单”用红底白字胶囊、“已取消”用灰底胶囊、金额 ¥75 用红色；一条卡内出现两种红与一种灰。
- 建议：允许助手回答根据内容类型自适应宽度（普通文本限宽、数据表格/卡片可占满对话区）；修正首屏滚动起始位置；把“第18单”编号胶囊与状态标签的颜色语义分开。

## 色彩与字体
- 页面主色使用深绿（AI 方块、在线状态点、选中标识），与侧栏品牌橙不同；标题 20px、副标题 13px 灰色，层级清楚。
- “已取消”灰胶囊 + 红底“第N单” + 红色金额，同一卡片红色出现两次；红色既表示序号又表示金额，语义被稀释。
- 输入框 placeholder“输入您的经营问题，按Ctrl+Enter发送…”字号 14px、灰度偏浅；右下角提示与按钮同在底部一行，“清空”为灰色描边、“发送”为浅绿描边，两者对比度接近。
- 建议：订单卡内红色只保留给“已取消/金额异常”其中一处；序号胶囊改用中性色；“发送”在输入非空时改为实心主色，与“清空”拉开层级。

## 留白与节奏
- 页面由“顶部身份卡 + Tab + 对话卡 + 输入区”四段构成，段间距约 20px，外部节奏一致。
- 对话卡内助手消息只占左侧约 25% 宽度，右侧约 700px 空白是页面最大的浪费；输入框与按钮之间的空白也偏大。
- 建议：对话内容区限制最大阅读宽度并居中或靠左留出合理边距；数据卡片可按可用宽度做 1–2 列布局，避免把结构化信息塞进窄列。

## 动效与交互反馈
- 静态截图无法验证发送、加载与流式输出。当前“发送”按钮在输入为空时呈浅色（禁用态合理），但可用态与禁用态差异需要更明确。
- 建议：发送后用户消息即时上屏、助手回答以流式文字 + 数据卡依次淡入（每条 180–220ms）；回答生成中显示打字指示；请求失败时给出可重试提示，而不是停留在空白。

## 与相邻页的一致性
- 与 09“商家聊天”同为对话界面，但 09 用浅绿/浅蓝气泡、16 用绿色主题 + 白色数据卡，两页消息壳与输入区样式不统一，应共享对话容器、输入框与发送按钮规范。
- 本页深绿主题与 10“经营统计”的绿色图标、12 的绿色 KPI 同源，但都没有与品牌橙形成明确分工。
- 四个功能 Tab 的形态与 14/15 的 Tab 不同，Tab 组件也需统一。

## 改造建议
- P0 必改：修正对话区宽度失衡，让助手数据卡不再被挤在窄列；修正首屏被裁切的第一张卡片。
- P1 建议：统一订单卡的颜色语义与 09 的对话样式，明确“发送”可用/禁用态。
- P2 可选：加入流式回答、数据卡依次淡入与失败重试反馈。
