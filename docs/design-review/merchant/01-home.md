# 商家首页（merchant/01-home）

- 截图：output/web-screenshots/merchant/01-home.png
- URL：/merchant/home
- 评审人：review-merchant

## 这页在讲什么
这页应在首屏回答“店铺今天是否正常、有哪些订单和消息需要马上处理”，当前画面先讲店铺档案，经营概览与订单中心被压在下方，首页更像资料页而不是经营驾驶舱。

## 主角 / 主动作
主角应是“今日待处理事项”，主动作应是处理订单或未读消息。当前最大、最完整的是店铺信息卡，右上角主按钮却是“编辑信息”；它是维护动作，不是每天高频经营动作，应与经营动作分层。

## 层级与构图
- 店铺信息卡占约 220px 高，信息足够完整，但昵称、评分、联系方式、营业时间同权平铺，首屏没有紧急性排序。
- “今日营业概览”四张 KPI 卡同权，第二张同时出现绿色外框和蓝色内框，像被选中的状态；页面没有说明选中含义，先移除或改成语义明确的告警/筛选状态。
- 订单中心只显示空状态和“查看全部订单”蓝链，主动作落在页面底部，首屏视线没有明确落点。
- 建议改为“待处理订单/未读消息/异常状态”优先的经营工作台，把店铺档案压缩成一条身份摘要；编辑信息降级为次级按钮。
- 工作量较大时按“待处理 > 今日数据 > 店铺资料 > 全部订单”排序，并让订单中心在首屏露出列表或明确空状态。

## 色彩与字体
- 品牌橙出现在 Logo、头像和侧栏选中态；店铺编辑按钮用深绿，订单中心链接用蓝色，KPI 又用蓝/绿/黄/红，主色语义不稳定。
- 标题、KPI、说明文字的字号层级基本能读，但大量彩色 emoji 承担图标职责，和店铺经营场景的专业感冲突。
- 建议固定“品牌橙承担品牌与主操作、绿色只表示成功、红色只表示异常/危险、蓝色只表示信息”，用 Element Plus 线性图标替换正文 emoji。

## 留白与节奏
- 卡片间距约 20px，局部呼吸感正常；问题是首屏把垂直空间给了静态资料和四张零值 KPI，真正的订单内容被挤到下方。
- 空订单面板约 300px 高，底部大面积空白没有被空状态、筛选或快捷动作利用。
- 建议缩短资料区和 KPI 区，把释放出的首屏空间给待处理列表。

## 动效与交互反馈
- 静态截图无法验证真实动效。当前没有可见的页面进入、KPI 更新、空状态或按钮反馈线索。
- 建议：卡片/按钮 hover 用 150–180ms ease-out；页面分区进入用 200–240ms 轻微上移淡入；今日数字首次加载做一次 240–320ms count-up，并在 `prefers-reduced-motion` 下直接显示终值。
- “编辑信息”和“查看全部订单”需要清晰的 hover、按压和键盘焦点状态，不能只靠颜色区分。

## 与相邻页的一致性
- 本页没有独立页面标题条，02/03/05 使用绿色标题条，04/10/12 使用白色标题区，首页是最明显的入口，却缺少同一套页面头部语言。
- 四张 KPI 的浅色底图标和左侧色条没有复用到订单、统计页；应抽成同一套 KPI/卡片规则。
- 侧栏选中态和 Logo 使用品牌橙，正文操作又使用绿/蓝，跨页主色语义应统一。

## 改造建议
- P0 必改：把首屏主角改为今日待处理订单和未读消息；删除或解释 KPI 卡的双重选中边框。
- P1 建议：压缩店铺档案，统一主操作、链接和状态颜色，替换结构性 emoji。
- P2 可选：加入一次性的 KPI count-up、分区淡入和按钮 hover/按压反馈。
