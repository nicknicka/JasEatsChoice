# 商家菜单管理（merchant/04-menu）

- 截图：output/web-screenshots/merchant/04-menu.png
- URL：/merchant/home/menu
- 评审人：review-merchant

## 这页在讲什么
这页负责让商家快速找到菜单、查看上架状态和关联菜品，并批量执行上下架或编辑动作；当前视觉先让用户读完一条很长的控制链，第一张真实菜单到页面中下部才出现。

## 主角 / 主动作
主角是菜单列表，主动作是新增菜单或编辑已有菜单。右上角“新增菜单”存在，但筛选、排序、批量工具和分页共同压过列表，导致编辑动作没有成为清晰的默认路径。

## 层级与构图
- 页面标题使用“【菜单管理】”方括号写法，和 02/05/10 的标题体系不一致；标题左侧、搜索右侧、绿色按钮再右侧，主次关系可读但不够稳定。
- 控制区连续叠了三层：标题/搜索、状态与排序、批量操作与分页。第一张菜单约从 y=495 开始，意味着 900px 首屏中超过一半被非列表内容占用。
- 批量工具条与分页同处一张白卡，分页 `Total 10` 的英文和中文界面混排，且分页控件在没有明显表格表头时缺少上下文。
- 每张菜单卡约 240px 高，名称、标签、菜品 chip、更新时间和四个操作按钮都堆在一起；菜品 chip 行较长时会把重要操作推到卡片下半部。
- 建议将筛选压缩成一行，批量操作固定在选中后的可撤消工具条中，分页移到列表末尾；菜单卡改为更短的摘要行或可展开详情。

## 色彩与字体
- 新增/上架/编辑/删除/导出分别使用绿、橙、蓝、红、灰，色彩丰富但没有统一的角色映射；红色删除和橙色下架都能读成危险或警告。
- 菜单名称使用 16px 左右、状态标签和菜品 chip 是 12–13px，文本层级可用；但多个浅色 pill 让卡片像标签集合，而不是菜单对象。
- 建议保留一套主色和一套状态色，把批量操作与行内危险操作降级；统一状态标签的尺寸、圆角和文字对齐。

## 留白与节奏
- 顶部控制区高度约 430px，列表只有约 400px 可视空间，浏览效率被控制区吞掉。
- 卡片内部留白偏大，尤其是名称到菜品 chip、chip 到更新时间之间，无法在一屏比较多个菜单。
- 建议首行控制区不超过约 140px，选中后才展开批量工具，卡片高度控制在 140–170px 以便一屏看到更多对象。

## 动效与交互反馈
- 静态截图无法验证批量选择、分页和编辑跳转；当前按钮看起来像一直可点，但选中态和批量操作触发关系不够明确。
- 建议：行/卡 hover 180ms 提升边框对比；勾选后用 180–220ms 滑入批量操作条；下架/删除使用明确的二次确认反馈；分页切换保持列表高度并显示轻量 loading。
- 选中的卡片不要同时使用浅色底和复选框两个等价信号，应统一由复选框和左边界状态共同表达。

## 与相邻页的一致性
- 与 07“菜品管理”几乎是同一套列表结构，应共享标题、搜索、批量操作、状态标签和分页组件。
- 本页的标题方括号、绿色渐变新增按钮、蓝色编辑按钮和菜单编辑页的表单按钮颜色不一致，跨页主操作缺少统一规则。
- 页面使用大量 emoji/彩色 tag；与订单页的状态标签相比，视觉语言没有收敛。

## 改造建议
- P0 必改：压缩首屏控制区，让第一张菜单提前出现；明确“新增”与“编辑”的主操作层级。
- P1 建议：统一标题、状态和操作颜色，缩短菜单卡，修正中英文混排的分页控件。
- P2 可选：加入批量操作条的展开/收起和列表切换反馈。
