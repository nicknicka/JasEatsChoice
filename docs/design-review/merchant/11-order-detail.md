## 这页在讲什么
这页负责让商家在一单里看清当前状态、顾客信息与时间信息；当前最上方的状态卡把“已完成”与四步进度条分开排布，中间留出一大段空白，进度条被孤立在状态卡下半部。

## 主角 / 主动作
主角是订单状态与其明细，主动作是刷新/打印单据，进度正常时以“返回”为主。深绿标题条内“刷新”“打印”“<返回”三个按钮大小一致，缺少主次；已完成订单里“刷新”权重高于“返回”，与实际使用频率不符。

## 层级与构图
- 标题条写明“订单详情”并带一侧订单号“08491969812951290”，信息齐全，但订单号被放在副标题位置、字号明显小于标题，查找订单号时需要重新定位。
- 状态卡内“✓已完成”在 y≈235，四步进度条在 y≈313，两者之间无连接线或分组，读起来像两个独立模块；进度条的步骤标签（待支付/待接单/制作中/已完成）只有 12px 浅灰，可读性偏弱。
- 进度条的四个节点大小一致、连线段为蓝色，但“已完成”节点用蓝底勾选，与已完成状态应有的成功色不符。
- “顾客信息”卡把昵称、电话、地址排成两列加一行，信息组织清晰；“时间信息”卡同样两列，结构一致，这部分可保留。
- 建议：把状态标题与进度条合并为一张紧凑卡，用一条完成的连接线自左向右串联四个节点；把订单号提到标题同级或右侧固定位置，方便对照。

## 色彩与字体
- 页面出现两种“完成”语义色：本页用蓝色圆形勾选表示已完成，而 02 订单列表用绿色标签表示已完成，跨页冲突。
- 标题条深绿底白字是全页最强色块，正文卡片全部白底灰边，对比稳定；进度条连线的蓝色与标题条的绿色又构成第三套语义色。
- 顾客信息卡内标签 13px 灰色、值 16px 深色，层级清楚；时间信息沿用同一规范。
- 建议：把“已完成”统一到成功绿，进度条连线沿用品牌主色；“刷新/打印”改为描边次级按钮，危险动作（如取消订单）如存在应单独隔离。

## 留白与节奏
- 状态卡高度约 190px，其中状态标题到进度条之间约 60px 空白，是卡内最明显的一处留白。
- 三张卡之间约 22px 间距，节奏一致；顾客信息卡与时间信息卡内容密度相近，观感平稳。
- 建议：压缩状态卡高度，把省下的空间给订单商品明细（当前首屏未出现菜品清单与金额）。

## 动效与交互反馈
- 静态截图无法验证刷新、打印和状态跳转。当前进度条没有“当前节点”动效线索。
- 建议：订单状态变更时，进度条当前节点以 220–260ms 高亮推进；刷新按钮在请求期间旋转；“打印”在无打印环境时给出明确提示而不是静默失败。

## 与相邻页的一致性
- 与 02/03“订单管理”共用深绿标题条，这点一致；但状态色（已完成=蓝）与列表页（已完成=绿）冲突，必须统一。
- 进度条组件在本页首次出现，02/03 的订单卡没有对应状态进度，建议抽成共享组件供列表与详情共用。
- “刷新/打印/返回”三按钮形态可作为全站页头操作区的规范模板。

## 改造建议
- P0 必改：统一“已完成”状态色并修正进度条节点配色；把订单号提到可与标题对照的位置。
- P1 建议：合并状态标题与进度条为一张紧凑卡，弱化刷新与打印的按钮权重。
- P2 可选：加入状态节点推进动效与刷新旋转反馈。
