# 支付密码设置（user/24-payment-password-setup）

- 截图：output/web-screenshots/user/24-payment-password-setup.png
- URL：/user/home/payment-password-setup
- 评审人：review-user

## 这页在讲什么

页面以安全提示和表单让用户设置支付密码。

## 主角 / 主动作

主角是支付密码表单，主动作是提交设置；蓝色安全提示面板比表单更醒目，小表单偏在左上，右侧和下方留下大片空白。

## 层级与构图

- 安全提示面板横跨内容区上方，白色表单卡尺寸过小，页面重心停在左上。
- 标题、说明、输入项和提交按钮没有形成逐步操作的结构，用户无法确认当前是第几步。
- 安全提示与表单之间的层级关系接近，提示内容反而像主内容。

## 色彩与字体

- 蓝色安全面板和橙色页面 accent 冲突，表单按钮也没有明确继承全站主按钮。
- 输入框、说明和错误提示缺少足够的字号和对比度差异。

## 留白与节奏

- 表单卡右侧和下方留白远大于表单内部留白，页面看起来像未铺满。
- 安全提示、表单和提交区之间缺少节奏分隔。

## 动效与交互反馈

- 静态截图无法验证动效；输入校验、密码强度、确认密码和提交成功需要逐步反馈。
- 失败后应保留已填内容并聚焦错误字段。

## 与相邻页的一致性

- 与钱包安全设置相比，安全等级和密码操作的视觉语言不一致。
- 与设置页相比，安全项没有独立的确认和返回路径。

## 改造建议

- P0 必改：把支付密码设置改成明确的单列步骤页，限制表单宽度并居中；将安全提示降为表单上方的辅助说明。
- P1 建议：统一安全类页面的主色和错误色；为输入、校验和提交按钮建立清晰状态。
- P2 可选：加入密码强度、确认密码和提交结果的过渡反馈。
