## 这页在讲什么

页面展示一笔已取消订单的状态、商家信息、商品信息和后续处理入口。

## 主角 / 主动作

主角是订单状态和当前可执行操作，主动作取决于取消原因或售后路径；顶部“已取消”和四步进度同时出现，语义冲突。

## 层级与构图

- 橙色状态条与四步进度并列，页面同时表达“正在推进”和“已取消”。
- 商家卡信息完整，但商品明细卡为空，用户看不到订单买了什么。
- 状态条、进度条和返回按钮占据首屏上半部，真正的处理入口被推低。

## 色彩与字体

- 橙色状态条、灰色步骤和“已取消”红/灰状态混用，用户无法判断当前色代表进行中还是终止。
- 订单号、商家名、商品名字号接近，关键状态没有形成强对比。

## 留白与节奏

- 商品空卡面积大，内容却为空，造成明显断裂。
- 状态区和商家区之间的距离较紧，商家区到空商品区又过松。

## 动效与交互反馈

- 静态截图无法验证动效；订单刷新后状态条和步骤应同步更新，取消后不应继续播放进度动画。
- 售后、重新下单等操作需要明确的 hover、禁用和结果反馈。

## 与相邻页的一致性

- 与“我的订单”相比，订单状态在列表和详情中使用了不同的颜色与文案结构。
- 与“订单确认”相比，商品行和金额规则没有继承。

## 改造建议

- P0 必改：先修复状态模型：已取消订单不再显示四步进度，改成“取消时间/原因 + 下一步操作”；补齐商品明细，不能保留空卡。
- P1 建议：统一订单详情中各信息块的字号和间距，把订单状态与订单号信息分层。
- P2 可选：让状态更新、售后提交和重新下单具备反馈与防重复提交。
