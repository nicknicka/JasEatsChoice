# 我的想吃列表（user/10-wish-list）

- 截图：output/web-screenshots/user/10-wish-list.png
- URL：/user/home/wish-list
- 评审人：review-user

## 这页在讲什么

页面用统计摘要、筛选工具和卡片列表管理用户标记为“想吃”的菜品与商家。

## 主角 / 主动作

主角是想吃列表，主动作是把条目转为订单或打开详情；四张统计卡和重复的绿色状态标签先于列表抢占注意力。

## 层级与构图

- 顶部四张统计卡横向铺满，数量本身不构成用户下一步，列表被推到下方。
- 缩略图使用大色块和被裁切的英文，无法区分菜品与商家。
- 绿色“想吃/可用”标签在每张卡上重复，状态呈现过于一致，失去筛选价值。

## 色彩与字体

- 绿色标签、彩色缩略图和蓝色详情按钮形成多重强调，和全站暖橙主色不统一。
- 菜品名、来源和标签的字号太接近，卡片缺少第一扫描点。

## 留白与节奏

- 统计卡和筛选栏之间距离紧凑，筛选栏与列表之间又突然变松。
- 卡片内部图片区高、正文区短，长列表看起来像图片墙而不是可操作列表。

## 动效与交互反馈

- 静态截图无法验证动效；从“想吃”转为下单或移除后应有原地状态变化和撤销入口。
- 筛选结果变化需要显示数量，不应静默重排。

## 与相邻页的一致性

- 与“商家查找”相比，同样使用缩略图和卡片，但这里的字段和按钮完全不同。
- 与“我的订单”相比，菜品状态标签的颜色语义没有被复用。

## 改造建议

- P0 必改：统一想吃条的图片裁切、标题和状态字段；把绿色标签改为有明确含义的状态，并让“去下单/查看详情”成为唯一主操作。
- P1 建议：压缩顶部统计卡或合并为一条摘要；让列表首屏至少露出两张完整卡片。
- P2 可选：为移除、下单和筛选结果变化增加原地反馈与撤销入口。
