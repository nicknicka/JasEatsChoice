## 这页在讲什么

页面把订单信息、菜品评价、星级和标签汇总到一次评价提交任务中。

## 主角 / 主动作

主角是待评价菜品和提交按钮，主动作是完成评分并提交；当前订单信息占上半部，菜品未知导致任务焦点失效。

## 层级与构图

- 三条“未知菜品”缩略图都显示“未”，用户无法确认评价对象。
- 星级、标签和文本输入分散排列，缺少“逐项评价→提交”的主路径。
- 金额使用红色，和评分强调色同时出现，视觉注意力落到金额而不是评价。

## 色彩与字体

- 红色金额、黄色星星、灰色未知图和蓝色控件没有统一语义。
- 菜品名缺失，标题层级只能靠“未知菜品”重复，页面看起来像数据错误页。

## 留白与节奏

- 订单信息与评价区之间没有显著分组，首屏留白被订单卡吃掉。
- 星级与标签区上下距离偏大，提交动作没有被固定或突出。

## 动效与交互反馈

- 静态截图无法验证动效；点星、选标签、输入评价都需要即时选中反馈。
- 提交后需要显示成功或失败的下一步入口，不能只清空表单。

## 与相邻页的一致性

- 与订单详情相比，这里没有复用同一套商品行和金额格式。
- 与“系统通知”相比，页面都使用重复标签，但评价页缺少自己的任务状态。

## 改造建议

- P0 必改：补齐菜品名称、图片和数量，先让用户知道在评价什么；把提交评价设为底部唯一主按钮并显示完成进度。
- P1 建议：统一评分、标签和金额的颜色语义，压缩订单信息区。
- P2 可选：为评分、标签选择和提交结果加入明确的过渡与状态反馈。
