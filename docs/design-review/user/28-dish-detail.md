## 这页在讲什么

页面用大幅菜品图、名称价格、分类热量和底部数量控件完成单道菜的加购确认。

## 主角 / 主动作

主角是菜品图和加购按钮，主动作是加入购物车；当前图片区是绿色占位和白色方块，菜名、价格等有效信息被弱化。

## 层级与构图

- 大块绿色媒体区占据首屏近一半，却没有真实菜品图，视觉重心落在失败占位上。
- 菜品名称、库存、价格、分类和介绍的层级过于平铺，底部数量控件与蓝色按钮分离在页面两端。
- 介绍区只有一行 `asd`，页面从大图直接跌入稀疏文本。

## 色彩与字体

- 绿色媒体区、红色价格、绿色库存和蓝色加购按钮同时出现，与全站暖橙主色冲突。
- 价格字号是页面最大文字，但名称和关键规格没有跟上层级；`¥12.00` 与“每份”距离过近。

## 留白与节奏

- 图片区和信息卡之间的过渡很硬，信息卡内部又反复出现不同尺寸的空行。
- 底部固定操作区没有与内容区形成稳定的安全间距。

## 动效与交互反馈

- 静态截图无法验证动效；数量增减、加入购物车成功和库存不足都需要就地反馈。
- 价格和数量变化应同步更新，不能只改数字不做状态提示。

## 与相邻页的一致性

- 与商家详情相比，菜品图片、分类标签和价格字段没有复用同一套组件。
- 与订单确认相比，数量控件和商品行的结构不一致。

## 改造建议

- P0 必改：替换菜品占位图并补齐真实分类、热量和介绍；把页面主色统一为暖橙，加购按钮使用唯一强调色。
- P1 建议：把价格、库存、规格和数量控件整理为一段信息区；底栏只保留数量与主操作。
- P2 可选：为加购、数量变化和库存状态增加过渡与确认。
