# 订单确认（user/05-order-confirmation）

- 截图：output/web-screenshots/user/05-order-confirmation.png
- URL：/user/home/order-confirmation
- 评审人：review-user

## 这页在讲什么

页面把商家、取餐方式、商品明细和应付金额集中到支付前的最后确认。

## 主角 / 主动作

主角是待支付订单和底部确认支付，主动作是核对金额后提交；蓝色到店自取区和重复商品行同时抢注意力。

## 层级与构图

- 商户信息、蓝色取餐区、商品明细和底部支付条纵向堆叠，信息层级完整但没有明显主次。
- 商品行重复出现，金额疑似重叠或被删除线切割，用户难以核对总价。
- 底部固定支付条贴近页面边缘，按钮和返回操作没有形成清晰的最后一步。

## 色彩与字体

- 蓝色取餐区和棕色商户/支付按钮属于两套强调体系。
- 金额使用红色和删除线组合，但没有说明优惠、原价和实付之间的关系。

## 留白与节奏

- 上部信息密度较高，商品明细下方却出现大块空白，页面从紧凑突然变松。
- 底部固定条遮住内容尾部，需要为滚动内容预留安全区。

## 动效与交互反馈

- 静态截图无法验证动效；数量、优惠和实付金额变化时应同步更新并显示反馈。
- 提交支付必须有 loading、防重复点击和失败后的可恢复状态。

## 与相邻页的一致性

- 与商家详情相比，商品行没有沿用同一套图片、规格和数量控件。
- 与订单详情相比，状态、金额和操作按钮的排版规则不一致。

## 改造建议

- P0 必改：修复商品重复和金额重叠，明确原价、优惠、实付三者的关系；让底部支付栏成为唯一主动作并预留滚动安全距离。
- P1 建议：把蓝色取餐区降为中性信息块，统一商户信息、商品行和支付栏的圆角与间距。
- P2 可选：为数量、优惠和支付状态加入过渡与确认反馈。
