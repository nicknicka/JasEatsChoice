# 内容提取失败处理分析

> **分析日期**: 2026-04-12
> **涉及模块**: ContentExtractionServiceImpl（内容提取服务）
> **问题级别**: P1（数据准确性问题）

---

## 一、问题概述

内容提取流程中，**AI 返回解析失败时，系统将其当作成功结果保存**，失败的提取记录和正常的混在一起，前端无法区分。

---

## 二、当前处理流程

```
用户提交URL
    → 创建 ContentSource（状态=PENDING）+ ExtractionTask（状态=PENDING）
    → doExtract() 异步执行：
        1. ContentFetcher 抓取内容
        2. ContentRecognizer（GLM-4.6V-Flash）AI 识别
        3. parseExtractionResult() 解析 AI 返回的 JSON
        4. 创建 ContentExtraction 记录
        5. 标记 ContentSource 状态 = SUCCESS
    → 前端展示提取结果
```

### 提取状态枚举（ExtractionStatus）

当前只有 4 个状态：

| 状态 | code | 含义 |
|------|------|------|
| PENDING | PENDING | 待提取 |
| PROCESSING | PROCESSING | 提取中 |
| SUCCESS | SUCCESS | 成功 |
| FAILED | FAILED | 失败 |

---

## 三、问题定位

### 核心问题：`parseExtractionResult()` 解析失败时返回假数据

**文件**: [ContentExtractionServiceImpl.java:478-512](JasEatsChoiceJava/src/main/java/com/xx/jaseatschoicejava/service/impl/ContentExtractionServiceImpl.java#L478-L512)

```java
private Map<String, Object> parseExtractionResult(String responseText) {
    try {
        // 正常解析 ...
        return result;
    } catch (Exception e) {
        log.error("解析提取结果失败: {}", responseText, e);
        // ← 问题：返回一个 dishName="提取失败" 的默认 Map，而不是抛异常
        Map<String, Object> defaultResult = new HashMap<>();
        defaultResult.put("dishName", "提取失败");
        defaultResult.put("description", "");
        defaultResult.put("ingredients", new ArrayList<>());
        // ...
        return defaultResult;
    }
}
```

### 问题链条

```
parseExtractionResult() 解析 AI 返回失败
    → 返回 dishName="提取失败" 的默认 Map（不抛异常）
    → doExtract() 拿到这个 Map，照常创建 ContentExtraction 记录
    → 标记 ContentSource.extractionStatus = SUCCESS   ← 错误！
    → 标记 ExtractionTask.taskStatus = SUCCESS         ← 错误！
    → 前端展示 dishName="提取失败" 的记录，和正常提取的混在一起
```

### 影响范围

| 影响 | 说明 |
|------|------|
| 数据准确性 | 数据库中存了 `dishName="提取失败"` 的假记录 |
| 前端展示 | 失败记录和成功记录放在一起，无法区分 |
| 误导用户 | 用户可能以为真的有一道菜叫"提取失败" |
| 状态标记 | ContentSource 和 ExtractionTask 都被标记为 SUCCESS |
| 原始数据丢失 | AI 返回的原始内容没有保存，无法事后分析或重试 |

---

## 四、各失败场景的处理现状

| 失败场景 | 发生位置 | 当前处理 | 是否合理 |
|----------|----------|----------|----------|
| 内容抓取失败 | ContentFetcher | 抛异常 → doExtract() catch → 标记 FAILED | **合理** |
| AI 识别服务异常 | ContentRecognizer | 抛异常 → doExtract() catch → 标记 FAILED | **合理** |
| AI 返回内容为空 | ContentRecognizer | 返回空字符串 → parseExtractionResult 解析失败 → 返回假数据 | **不合理** |
| AI 返回格式错误（非 JSON） | parseExtractionResult() | catch → 返回 dishName="提取失败" 的假 Map | **不合理** |
| AI 返回 JSON 缺少字段 | parseExtractionResult() | putIfAbsent 补默认值 | **合理** |
| JSON 序列化失败（ingredients/steps） | updateExtraction() | log.error 后异常被吞掉 | **不合理**（静默失败） |

### 方案概览

```
                    修复前                              修复后
            ┌─────────────────┐              ┌─────────────────┐
            │  AI返回解析失败   │              │  AI返回解析失败   │
            └────────┬────────┘              └────────┬────────┘
                     │                                │
                     ▼                                ▼
            ┌─────────────────┐              ┌─────────────────┐
            │ 返回默认Map      │              │ 抛出异常/返回空   │

            └────────┬────────┘              └────────┬────────┘

```

### Phase 1：parseExtractionResult 不再返回假数据（P1）

**修改文件**: [ContentExtractionServiceImpl.java:478-512](JasEatsChoiceJava/src/main/java/com/xx/jaseatschoicejava/service/impl/ContentExtractionServiceImpl.java#L478-L512)

**改动**：解析失败时抛异常，让 `doExtract()` 走失败分支。

```java
private Map<String, Object> parseExtractionResult(String responseText) {
    try {
        String json = extractJson(responseText);
        Map<String, Object> result = objectMapper.readValue(json, ...);
        // 确保必要字段存在
        result.putIfAbsent("dishName", "未知菜品");
        // ...
        return result;
    } catch (Exception e) {
        log.error("解析提取结果失败: {}", responseText, e);
        // 改为抛异常，而不是返回假数据
        throw new RuntimeException("AI识别结果解析失败: " + e.getMessage(), e);
    }
}
```

**效果**：`doExtract()` 的 catch 分支会正确标记 FAILED 状态，不创建假记录。

### Phase 2：增加 PARSE_FAILED 中间状态（P1）

**修改文件**: [ExtractionStatus.java](JasEatsChoiceJava/src/main/java/com/xx/jaseatschoicejava/enums/ExtractionStatus.java)

**新增枚举值**：

| 状态 | code | 含义 | 前端处理建议 |
|------|------|------|-------------|
| PARSE_FAILED | PARSE_FAILED | 内容抓到但解析失败 | 显示"解析失败，点击查看原始内容"，支持重新解析 |

```java
PARSE_FAILED("PARSE_FAILED", "解析失败");
```

**doExtract() 中区分失败类型**：

```java
} catch (Exception e) {
    // 区分是"抓取失败"还是"解析失败"
    if (e.getMessage() != null && e.getMessage().contains("AI识别结果解析失败")) {
        source.setExtractionStatus(ExtractionStatus.PARSE_FAILED.getCode());
        // 保存原始AI返回，方便排查和手动恢复
        source.setErrorMessage("解析失败，原始AI返回: " + aiResponse);
    } else {
        source.setExtractionStatus(ExtractionStatus.FAILED.getCode());
        source.setErrorMessage(e.getMessage());
    }
    contentSourceMapper.updateById(source);
    // ...
}
```

### Phase 3：前端区分展示（P2）

**修改文件**: 前端内容提取相关组件

**展示策略**：

| 状态 | 展示方式 |
|------|----------|
| SUCCESS | 正常展示提取的菜品信息 |
| FAILED | 显示"抓取失败"+ 重试按钮 |
| PARSE_FAILED | 显示"内容已抓取，解析失败"+ 查看原始内容 + 重新解析按钮 |
| dishName="提取失败"（历史脏数据） | 识别为脏数据，归入失败分组 |

## 六、历史脏数据处理

修复后，数据库中已存在的 `dishName="提取失败"` 记录需要清理：

```sql
-- 查看脏数据量
SELECT COUNT(*) FROM content_extraction WHERE dish_name = '提取失败';

-- 将关联的 ContentSource 状态修正为 FAILED
UPDATE content_source
SET extraction_status = 'FAILED', error_message = '历史脏数据：AI返回解析失败'
WHERE id IN (
    SELECT source_id FROM content_extraction WHERE dish_name = '提取失败'
);
```
