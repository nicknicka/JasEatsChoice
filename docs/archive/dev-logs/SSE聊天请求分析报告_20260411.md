## 七、问题总结与优化建议

### 7.1 高优先级

#### 问题1：阶段2 冗余 LLM 调用（浪费 11.4s / 51.5%）

**现状：** 阶段1 已生成完整回答，阶段2 再次调用 LLM 做格式化输出。

**优化方案：**
- 方案A：直接将阶段1 结果流式输出，跳过阶段2 → **节省约11秒**
- 方案B：将阶段2 改用轻量模型（如 glm-4-flash）做快速格式化 → **节省约7-8秒**
- 方案C：在阶段1 中直接要求 LLM 输出最终格式，合并两阶段 → **节省约11秒**

#### 问题2：SSE 事件元数据全部为 null

**现状：** agentName、toolName、inputs、output 均未填充。

**优化方案：**
- 在 `SSEAgentListener` 中从 `AgenticScope` 和工具执行上下文中提取信息
- 填充 agentName（如 "NutritionGuideAgent"）、toolName（如 "generateDietAdvice"）
- 前端可据此展示精确的进度指示器

### 7.2 中优先级

#### 问题3：Supervisor 路由规划耗时 2.3s

**现状：** SupervisorAgent 的 LLM 调用耗时 2,270ms 仅用于选择调用哪个 Agent。

**优化方案：**
- 使用更快模型（如 glm-4-flash）做路由决策
- 对于简单意图，可使用规则引擎预匹配，跳过 LLM 路由

#### 问题4：NutritionGuideAgent 工具调用后 LLM 整理耗时 6.1s

**现状：** 工具返回数据后，LLM 花了 6.1s 整理成 225 字符的摘要。

**优化方案：**
- 优化 prompt，减少不必要的推理步骤
- 考虑使用更快的模型
- 如果工具返回已经是结构化数据，可用模板渲染代替 LLM 整理

### 7.3 低优先级

#### 问题5：日志过于详细

**现状：** 每个 SSE 事件输出约 20 行日志，包含重复的分割线、完整 JSON 数据等。

**优化方案：**
- 生产环境压缩日志，单条事件记录为1-2行
- 详细日志仅在 DEBUG 级别输出
- 减少重复的分割线和换行
