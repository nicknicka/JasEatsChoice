## 新发现的问题

Phase 1 修复了截断，但暴露了三个更深层的问题：

### 问题链条

```
Planner不停止 → 反复调用Agent → 触发5次上限
    ├── 问题1: UserPreferenceAgent未经授权修改了用户偏好数据（数据安全）
    ├── 问题2: 违反禁止规则（重复调用+超过3次上限）
    └── 问题3: 最终回答变成"偏好修改确认"而非"菜品推荐"（回答偏离）
```

### 数据对比

| 维度 | 期望 | 实际 |
|------|------|------|
| Agent调用次数 | 2次 | 5次（达到上限） |
| 总耗时 | ~12秒 | **41秒** |
| 最终回答 | 菜品推荐列表 | "已成功调整您的饮食偏好标签..." |
| 用户偏好 | 不变 | **被覆盖为素食/低卡/过敏** |

---

## 根因

三层问题叠加：

1. **Planner层** — 不知何时停止，第2轮拿到推荐结果后继续"优化"
2. **Agent层** — UserPreferenceAgent 不区分查询与修改，收到"调整"就写入
3. **策略层** — `responseStrategy=LAST` 取最后一次结果，调用链跑偏后回答必然错误

---

## 待修复方案

| 优先级 | 修复项 | 要点 | 工作量 |
|--------|--------|------|--------|
| P0 | UserPreferenceAgent 区分查询与修改 | 推荐场景只读，明确指令才写 | 10分钟 |
| P0 | Planner 停止条件 + 调用上限 3→3 | 拿到推荐结果立即 done，`maxAgentsInvocations` 从 5 降至 3 | 10分钟 |
| P1 | 响应策略保底 | 保持 LAST，靠前两项保证调用链正确；或 Controller 层记录推荐结果做兜底 | 20分钟 |

**预期效果**：调用 2 次 Agent / 耗时 ~12秒 / 回答正确 / 偏好数据不被篡改
