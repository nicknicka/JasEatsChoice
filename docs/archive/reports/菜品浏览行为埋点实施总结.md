## 项目背景

### 业务现状

佳食宜选系统采用**用户协同过滤 + 内容过滤混合推荐算法**，结合用户历史偏好、地理位置、天气、时段等多维度特征，为用户推荐合适的饮食。

### 推荐系统架构

```
用户特征 → 协同过滤 → 相似用户 → 推荐菜品
         ↓
内容过滤 → 相似菜品 → 推荐菜品
         ↓
多维度融合 → 最终推荐列表
```

### 用户行为权重体系

| 行为类型 | 权重 | 说明 |
|---------|------|------|
| view (浏览) | 1 | 用户查看菜品详情 |
| click (点击) | 2 | 用户点击菜品卡片 |
| favorite (收藏) | 3 | 用户收藏菜品 |
| share (分享) | 4 | 用户分享菜品 |
| order (下单) | 5 | 用户下单购买 |
| reject (拒绝) | -3 | 用户拒绝推荐 |

## 问题分析

### 发现的问题

**时间：** 2026-03-27
**发现方式：** 数据库行为记录分析

**问题详情：**
- ❌ 只有推荐列表浏览记录：**360条**
- ❌ 只有拒绝记录：**4条**
- ❌ **缺少具体菜品浏览记录：0条**

### 问题影响

1. **推荐算法缺陷**
   - 无法追踪用户对具体菜品的兴趣
   - 协同过滤算法缺少关键数据
   - 推荐准确度受限

2. **数据维度缺失**
   - 只有推荐列表层面的数据
   - 缺少菜品详情层面的用户行为
   - 无法进行精细化推荐

3. **业务影响**
   - 推荐系统效果不佳
   - 用户体验有待提升
   - 转化率无法优化

### 问题根因

**代码层面：**
- 后端接口缺少行为埋点调用
- 前端未传递用户身份信息
- 缺少统一的埋点工具类

**数据层面：**
- `user_behavior` 表存在但未被充分利用
- 现有的 `RecommendController` 有部分埋点，但不完整

## 解决方案

### 核心策略

**复用现有基础设施**，最小化代码改动：
- ✅ 复用 `UserBehaviorService`（已有异步记录能力）
- ✅ 复用 `user_behavior` 表（无需新建表）
- ✅ 创建工具类简化埋点逻辑
- ✅ 前后端配合传递用户ID

### 实施原则

1. **非侵入性**：不影响现有业务逻辑
2. **高性能**：异步记录，不阻塞主流程
3. **可扩展**：工具类可复用，便于扩展
4. **向后兼容**：未登录用户不影响使用

**功能：** 统一从请求中获取用户ID的逻辑

```java
public class UserIdentityUtil {

    // 备选从 JWT Token 解析
    public static String extractUserId(HttpServletRequest request)
```

**关键特性：**

### 前端实现

#### 1. Electron端 - 添加用户ID请求头

**文件：** `JasEatsChoiceFront/src/renderer/src/utils/api.js`

**修改位置：** 请求拦截器（约第140行）

**修改内容：**
```javascript
api.interceptors.request.use((config) => {
  // ... 原有逻辑 ...

  if (token) {
    config.headers.Authorization = `Bearer ${token}`

    // 从JWT token解析用户ID，添加到请求头用于行为追踪
    const decoded = decodeJwt(token)
    if (decoded && decoded.userId) {
      config.headers['X-User-Id'] = decoded.userId
    }
  }

  return config
})
```

**关键特性：**
- 自动从JWT Token解析用户ID
- 所有请求自动携带X-User-Id
- 无需页面级代码修改

#### 2. UniApp端 - 实现埋点工具

**文件：** `JasEatsChoiceUniApp/src/utils/behaviorTracking.js`（新建）

**功能：** 批量队列发送的行为追踪工具

```javascript
export const behaviorTracker = {
  // 菜品浏览
  trackDishView(dishId, options)

  // 菜品点击
  trackDishClick(dishId, options)

  // 菜品收藏
  trackDishFavorite(dishId, options)

  // 菜品分享
  trackDishShare(dishId, options)

  // 列表浏览
  trackDishListView(listType, itemCount, options)

  // 商家浏览
  trackMerchantView(merchantId, options)
}
```

**关键特性：**
- 批量队列发送（10条或5秒触发）
- 支持多种行为类型
- 失败自动重试
- 页面卸载自动发送

**使用示例：**
```javascript
import { behaviorTracker } from '@/utils/behaviorTracking.js'

// 菜品详情页
onLoad(options) {
  behaviorTracker.trackDishView(this.dishId, {
    context: { source: 'dish_detail_page' }
  })
}

// 菜品列表页
onLoad(options) {
  // 页面加载时记录列表浏览
  behaviorTracker.trackDishListView('search_list', this.dishList.length, {
    context: { source: 'search_page' }
  })
}

// 菜品点击
onDishClick(dish) {
  behaviorTracker.trackDishClick(dish.id, {
    context: { source: 'dish_list', position: this.dishList.indexOf(dish) }
  })
  // 跳转到详情页
  uni.navigateTo({ url: `/pages/dish/detail?id=${dish.id}` })
}
```

```javascript
      dishList: [],
      listType: 'search_list' // 或 'category_list', 'merchant_list'
```

```javascript
// 分享菜品
onShare(dish) {
  // 记录分享行为
  behaviorTracker.trackDishShare(dish.id, {
    context: {
      source: 'dish_detail_page',
      shareType: 'wechat' // 或 'friend', 'moment' 等
    }
  })

  // 调用分享接口
  uni.share({
    provider: 'weixin',
    type: 0,
    title: dish.name,
    href: `/pages/dish/detail?id=${dish.id}`
  })
}
```

### 附录F：常见问题FAQ

**Q1: 为什么异步记录不阻塞主流程？**
A: 使用 `@Async` 注解，方法在独立线程池中执行，主线程立即返回。

**Q2: 如何保证数据不丢失？**
A:
- 异常处理完善，记录失败不影响业务
- 可添加重试机制
- 重要日志记录到文件

**Q3: 如何处理未登录用户？**
A:
- `UserIdentityUtil.extractUserId()` 返回 null
- `BehaviorTrackingUtil` 检测到 null 后直接返回，不记录
- 不影响正常业务流程

**Q4: 数据库压力如何？**
A:
- 异步批量写入，压力可控
- 可调整线程池参数
- 建议实施读写分离

**Q5: 如何验证埋点是否生效？**
A:
- 查询数据库 `user_behavior` 表
- 检查日志中的埋点调用记录
- 使用监控工具跟踪接口响应时间
