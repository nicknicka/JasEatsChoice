# 接口修复计划

生成时间：2026-04-15
适用范围：佳食宜选后端、桌面端、小程序端接口联调修复

## 一、修复目标

1. 优先恢复 `P0` 主链路接口可联调能力，确保用户资料、地址、订单状态等核心流程可用。
2. 收敛前后端字段、请求方式、路径前缀差异，减少 404、405、字段丢失和状态流转错误。
3. 修复后同步更新文档与验证结果，形成可持续回归基线。

## 二、分阶段计划

### 第一阶段：核心协议兼容修复（P0）

- 修复用户资料更新接口语义错位
  - 统一小程序端资料更新走 `/v1/users/{userId}/info`
  - 后端补齐 `avatar`、`gender`、`birthday`、`bio`、`goal/taste/allergies` 等字段兼容
- 修复地址接口字段错位
  - 小程序接口层统一把 `name/phone` 映射为 `receiverName/receiverPhone`
  - 自动补齐 `userId`
  - 删除、设默认等接口统一传正确参数
- 修复订单状态更新协议
  - 后端同时兼容查询参数和请求体传 `status`
  - 小程序端取消订单改为 `PUT`
  - 桌面端确认收货状态统一收敛到 5 状态体系

### 第二阶段：接口方法与路径对齐（P1）

- 修复小程序端用户模块方法错误
  - 修改密码 `POST -> PUT`
  - 上传头像 `POST -> PUT`
- 修复通知模块路径
  - `/v1/notifications/*` 与 `/notifications/*` 前缀统一
- 修复节日、心愿单等桌面端旧路径
  - 节日模块 `/festivals`、`/events/custom`、`/recommendations/{id}/feedback`
  - 心愿单审核/申诉改为 DTO 提交方式

### 第三阶段：存量未实现接口收敛（P1/P2）

- 清理小程序端未落地旧接口
  - 优惠券
  - 聊天
  - 拼单
  - 钱包
  - 历史记录
- 对暂未实现能力给出明确策略
  - 已实现则对齐封装
  - 未实现则下线前端入口或补后端接口

### 第四阶段：回归验证与文档回写

- 逐项回填修复结果到字段对接报告
- 依据 `API测试方案.md` 执行 P0/P1 冒烟
- 输出剩余问题清单和下一轮修复建议

## 三、本轮执行顺序

1. 第一阶段：核心协议兼容修复
2. 第二阶段中最关键的方法错误修复
3. 运行最小回归检查
4. 输出本轮完成项与下一步计划

## 四、拼单主链真值收口执行结果（2026-04-17）

- 后端补齐拼单邀请接口：`POST /api/v1/group-orders/group-orders/{groupOrderId}/invite`
- 后端拼单支付接口已支持：
  - 余额支付真实闭环
  - 微信支付模拟返回
  - 支付宝支付模拟返回
- 后端详情与列表已统一以后端真值字段为准：
  - `members`
  - `participants`
  - `currentCount`
  - `maxParticipants`
  - `currentUserJoined`
  - `currentUserPaid`
  - `locked`
  - `confirmedTime`
  - `canConfirm`
  - `canEdit`
  - `canLeave`
  - `canPay`
- 小程序端详情页、选菜页、结算页、聊天拼单页已改为消费上述真值字段，不再自行猜测成员、人数和锁单状态
- 小程序端微信支付、支付宝支付已明确改为模拟流程展示

### 当前状态流转

- `-1`：草稿
- `0`：待确认/待支付
- `1`：已全部支付，待接单
- `2-4`：商家处理态
- `5`：已完成
- `6`：已取消

### 当前数据基线

- 拼单成员以 `t_group_order_member` 的有效成员记录为准，不再以 `t_group_order_dish.user_id` 反推作为正式协议基线
- 拼单人数以 `currentCount` 和 `maxParticipants` 为准，均由后端生成并返回
- 锁单状态以 `t_group_order.locked` 为准
- 确认成团时间以 `t_group_order.confirmedTime` 为准
- 当前用户拼单操作权限以后端返回字段为准：
  - `currentUserJoined`
  - `currentUserPaid`
  - `canConfirm`
  - `canEdit`
  - `canLeave`
  - `canPay`

### 当前业务约束

- 未确认成团前：允许成员改菜，允许未支付成员退出
- 已确认成团后：锁定选菜，禁止继续改菜、继续加入、退出拼单
- 发起人不能直接退出，只能取消拼单
- 所有需支付成员支付完成后，群订单流转到 `1`
- 微信支付、支付宝支付仅用于联调与演示，不接真实支付回调

### 当前后续项

- 目标环境需要执行数据库迁移 `V2026041701__create_group_order_member_table.sql`，否则成员真表与真字段不会生效
- `groupOrder` 与 `group-order-api` 两套历史拼单封装仍可继续做低优先级清理，但不影响当前主链联调
- 微信支付、支付宝支付按既定范围继续保持模拟实现，不进入真实商户资质、签名与回调闭环
