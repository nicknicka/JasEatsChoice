```java
public SmartRecommendationAgent smartRecommendationAgent(
```

### 问题2: Supervisor未注册子Agent

#### 🔴 严重程度：高

#### 问题描述

`SupervisorAgent` 在构建时没有调用 `.subAgents()` 方法注册子Agent。

**当前实现**:
```java
@Bean
public SupervisorAgent supervisorAgent(ChatModel chatLanguageModel, ChatMemory chatMemory) {
    log.info("构建SupervisorAgent（监督代理）...");

    return AgenticServices
            .supervisorBuilder(SupervisorAgent.class)
            .chatModel(chatLanguageModel)
            .chatMemoryProvider(memoryId -> chatMemory)
            .name("SupervisorAgent")
            .description("智能调度Agent，协调多个L2领域Agent完成复杂任务")
            // ❌ 缺少：.subAgents(...)
            .outputKey("supervisorResult")
            .supervisorContext("""
                # 可用的领域专家Agent
                1. SmartRecommendationAgent - 智能推荐专家
                2. HealthManagementAgent - 健康管理专家
                3. FullOrderAgent - 订单处理专家
                ...
                """)
            .contextGenerationStrategy(
                SupervisorContextStrategy.CHAT_MEMORY_AND_SUMMARIZATION
            )
            .responseStrategy(
                SupervisorResponseStrategy.SCORED
            )
            .maxAgentsInvocations(10)
            .build();
}
```

#### 影响分析

| 影响项 | 描述 | 后果 |
|--------|------|------|
| **子Agent注册** | 未调用 `.subAgents()` | Supervisor无Agent可用 |
| **supervisorContext文本** | 描述了4个Agent | 纯文本，无实际作用 |
| **Agent调用** | Supervisor无法调用子Agent | 退化为普通Agent |
| **多Agent协作** | 无法协调多个Agent | 只能单一LLM调用工具 |

**本质问题**:
- `supervisorContext` 中的Agent描述只是文本提示
- Supervisor实际可用的Agent = `.subAgents()` 注册的Agent
- 当前：文本描述4个，实际注册0个

#### 统计数据

```
文本描述的子Agent: 4个
  - SmartRecommendationAgent
  - HealthManagementAgent
  - FullOrderAgent
  - IntelligentAssistantAgent

实际注册的子Agent: 0个

注册率: 0/4 = 0%
```

### 问题3: Agent实例类型不匹配

#### 🔴 严重程度：高

#### 问题描述

Agent实例是代理对象（Proxy），不能直接作为工具传递或注册。

**错误示例**:
```java
// ❌ 错误：将Agent作为工具传递
@Bean
public StreamingIntelligentAssistantAgent streamingAgent(...) {
    return AiServices.builder(StreamingIntelligentAssistantAgent.class)
        .tools(
            workflowSmartRecommendationAgent,  // ❌ Agent实例，会报错
            workflowHealthManagementAgent,     // ❌ Agent实例，会报错
            workflowFullOrderAgent             // ❌ Agent实例，会报错
        )
        .build();
}
```

**错误信息**:
```
IllegalConfigurationException: Object 'jdk.proxy3.$Proxy167'
does not have any methods annotated with @Tool
```

#### 原因分析

```
Agent实例 = Spring代理对象 (CGLIB Proxy)
    ↓
包含 @Tool 方法？
    ↓
❌ 否：代理对象无法识别原始类的 @Tool 注解
```

**架构冲突**:

```
Spring IoC容器需求:
  - 使用 @Component/@Service 标记
  - 使用 @Resource/@Autowired 注入
  - 生成CGLIB代理对象（AOP、事务等）

LangChain4j AgenticServices需求:
  - 扫描原始类的 @Tool 注解
  - 不能是代理对象
  - 需要 raw class instance
```

---

#### ✅ 解决方案

**方案1: Agent作为子Agent（推荐）**

```java
// ✅ 正确：使用 .subAgents() 而非 .tools()
@Bean
public SupervisorAgent supervisorAgent(...) {
    return AgenticServices
        .supervisorBuilder(SupervisorAgent.class)
        .subAgents(  // ✅ Agent注册在这里
            smartRecommendationAgent,
            healthManagementAgent,
            fullOrderAgent
        )
        .build();
}
```

**方案2: 只使用工具类（当前采用）**

```java
// ✅ 临时方案：不传递Agent，只传工具类
@Bean
public StreamingIntelligentAssistantAgent streamingAgent(...) {
    return AiServices.builder(StreamingIntelligentAssistantAgent.class)
        .tools(
            // ✅ 工具类可以正常工作
            userProfileTools,
            recommendationQueryTools,
            nutritionAnalysisTools,
            orderQueryTools
        )
        .build();
}
```

**方案3: 手动创建非代理实例（高级）**

```java
// ⚠️ 高级方案：手动创建Agent避免代理
private SmartRecommendationAgent createSmartRecommendationAgent() {
    // 使用 AgenticServices 创建（非Spring Bean）
    return AgenticServices.agentBuilder(SmartRecommendationAgent.class)
        .chatModel(chatModel)
        .tools(/* 手动注入工具 */)
        .build();
}
```

**推荐方案**:
- **Supervisor**: 使用 `.subAgents()` 注册L2 Agent
- **L2 Agent**: 使用 `AgenticServices.agentBuilder()` 构建
- **工具类**: 保持当前方式（@Component + @Tool）

### 问题4: @Agent注解缺失

#### 🟡 严重程度：中

#### 问题描述

设计文档中提到的 `@Agent` 注解在 LangChain4j 1.12.1-beta21 中不存在。

**设计期望**:

```java
        营养分析专家，能够：
        **核心能力：**
        1. 分析食物营养成分
        2. 计算每日热量需求
        """,
    outputKey = "nutritionResult"
)
String chat(@UserMessage String userMessage);
```

**实际情况**:
```bash
javap检查结果：没有 @Agent 注解
```

#### API验证

**检查命令**:
```bash
javap -cp langchain4j-1.12.1.jar dev.langchain4j.service.annotation.Agent
# 输出：错误：找不到类
```

**检查结果**:
```
langchain4j-core-1.12.1.jar:
  ❌ dev.langchain4j.service.annotation.Agent 不存在

langchain4j-agentic-1.12.1-beta21.jar:
  ❌ dev.langchain4j.agentic.annotation.Agent 不存在
  ❌ 任何包含 "Agent" 的注解都不存在
```

#### 影响分析

| 设计特性 | 实际支持 | 替代方案 |

```java
// Agent B 读取状态

```

**实际情况**:


| 场景 | 需求 | 当前状态 | 后果 |
|------|------|---------|------|
| **多Agent协作** | Agent间传递数据 | ❌ 不支持 | 无法协作 |
| **上下文共享** | 用户信息、历史记录 | ❌ 不支持 | 重复查询 |
| **结果汇总** | Supervisor汇总结果 | ❌ 不支持 | 信息丢失 |

| **Supervisor** | 强推理能力 | glm-4-flash | ⚠️ 规划能力可能不足 |
| **L2 Agent** | 快速响应 | glm-4-flash | ✅ 合适 |
| **L1 Agent** | 快速响应 | glm-4-flash | ✅ 合适 |

**成本对比**:

```
单次复杂任务调用：

当前方案（单模型）:
  Supervisor: glm-4-flash × 1次
  NutritionAgent: glm-4-flash × 1次
  RecommendationAgent: glm-4-flash × 1次
  总成本: 3次 flash模型调用

推荐方案（双模型）:
  Supervisor: glm-4-plus × 1次
  NutritionAgent: glm-4-flash × 1次
  RecommendationAgent: glm-4-flash × 1次
  总成本: 1次plus + 2次flash

成本差异：plus ≈ 5× flash
实际影响：总成本约 1.7倍，但质量显著提升
```

```java
    public AiServiceListenerRegistrar aiServiceListenerRegistrar() {

        return listenerRegistrar;
```
